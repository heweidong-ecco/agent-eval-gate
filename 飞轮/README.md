# 飞轮/ · 数据飞轮与主动学习(反馈 → 案例库 → 提炼 → 评估 → 上线)

> 定位:让 Agent「越用越聪明」。依据:B `06-优化-数据飞轮与主动学习`(闭环与四策略)+ `02-方法论-工程纪律与CI-CD`(评估门禁)。
> 目录本身是"回收入口 + 约定",实际反馈采集在运行期(见下),结构化产物落到本目录。

## 闭环(引自 B)

```
用户/人工反馈 ──► 案例结构化入库 ──► 半自动提炼(规则/Few-shot)
      ▲                                        │
      │                                        ▼
  优化上线 ◄── 评估集回归通过 ◄── 提示/知识库更新
```

## 目录约定

```
飞轮/
  README.md           本文件(回收入口 + 操作约定)
  反馈/                原始反馈信号(点赞/点踩/纠错/人工复审/投诉;脱敏后落这里或只留指针)
  案例库/              结构化案例(成功/失败,带标签:场景/模块/根因/复现);失败即补 case
  提炼/                周期蒸馏产物(规则 / Few-shot 示例 / 防错规则)→ 须过人工审核队列
  上线/                上线记录(评估回归结果 + 人工审核通过 + 版本/变更链接)
```

## 操作约定(参考 B 实施步骤)
1. **建反馈通道**:显性(点赞/点踩/纠错)+ 隐性(行为数据);脱敏后按批导入 `反馈/`。
2. **建案例库**:`案例库/` 结构化存储 + 标签;线上新失败 → **立即补 case**(失败即补,`eval/README.md`)。
3. **建流水线**:定期(周)跑「提炼 → 人工审核 → 评估 → 上线」;产物先落 `提炼/`,再推 `eval/cases/` 与 `../eval/evals.json`。
4. **接评估门禁**:所有提炼结果先过 `eval/阈值.md` 回归,通过才发布;产物必须过**人工审核队列**(防劣化,这是 B 的风险控制)。
5. **记忆新鲜度**:遗忘曲线/新鲜度衰减;被反复确认的记忆权重上升(`05-模块-记忆模块`)。
6. **主动学习采样**:低置信度/边缘案例优先送人工标注(信息增益最大化),标注结果回流评估集。
7. **定期复盘**:月度分析飞轮效果(指标:反馈回流率、评估集规模/更新频率、人工介入率趋势、迭代优化周期),调整蒸馏策略。

## ⚠️ 2026-09-13 形态适配:四腿里**只有一腿有真实输入**(D-17 / `DEC-014` §5 行动 7)

飞轮的**机制**其实已经存在一半,缺的是"**输入**"。逐腿判定:

| 腿 | 判定 | 现状 / 原因 | 触发条件 |
|---|---|---|---|
| **失败回灌**(线上新失败 → 立即补 case) | ✅ **已在跑** | `eval/cases/` **22 条** + README 机制 + CI 完整性守卫 + `.claude/hooks/failure-sentinel.sh`;**这是飞轮的第一腿,不需新建** | — |
| 反馈通道(点赞/点踩/纠错) | ⛔ **无此项** | **无外部用户**(唯一使用者 = 业务方本人),无反馈来源 | 出现第一个外部使用者 |
| 主动学习采样(低置信送标注) | ⛔ **无此项** | 需要人工标注预算;**业务方已定夺近期不投入标注**(见 `T1b`/`DEC-008`,同类"会空转")) | 有标注预算时 |
| 月度复盘 | ⛔ **无此项** | 无人读的周期性仪式 = **空转**(同日历次判定的同一理由) | 有第二使用者 |

> ⇒ **不做的事**:不创建 `反馈/`、`提炼/`、`上线/` 三个空目录 —— **空目录不是机制,是装饰**
> (与 `DEC-014` 判"监控面板占位该删"同一条理由)。`案例库/` 的职能由 `eval/cases/` 承担。
> **判定依据与原因全文**:`docs/decisions/DEC-014-阶段5-6形态适配.md` §3 U5。

## 纪律
- 自动提炼可能引入偏差 → 一切产物经人工审核后再上线;反馈数据涉及用户信息 → 脱敏后用(合规)。
- 飞轮指标挂 L3/北极星:人工介入率持续下降、CSAT/完成率趋势上升 = 飞轮在转。
