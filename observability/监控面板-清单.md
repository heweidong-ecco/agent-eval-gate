## 0. 本形态下「面板」是什么(先读这段)

**没有常驻仪表盘** —— 门不是服务,无常驻进程可挂 Grafana。
本形态的等价物 = **每次运行的落盘产物 + CI 结果**:

| 原"面板"要回答的 | 本形态的承接物 |
|---|---|
| 现在健康吗? | `eval/runs/<run_id>.summary.md` + exit code(0/1/2/3) |
| 指标是多少? | `eval/l1_baseline.json`(**机读**)+ 报告 JSON 的 `summary` |
| 怎么下钻? | `eval-gate trace --run <id>`(span 树)+ stderr 结构化日志 |
| 告警给谁? | **CI 红 + exit code**(见 §2) |

## 2. 告警规则(**本形态的"告警"是什么**,D-17 / B2 正式定义)

**告警 = exit code + CI 红 + stderr 结构化日志。** 无外部通道。

| 级别 | 本形态的触发 | 谁看 |
|---|---|---|
| **P0 阻断发布** | `exit 1`(有 blocker:红队突破 / L2 未达阈 / L1 系统错误率 / 门自身开销超阈) | CI 红,业务方 |
| **P0 运行错误** | `exit 3`(配置/IO/被测配额耗尽⇒aborted)。⚠️ **不是质量不合格** —— 见 `docs/故障场景应对手册.md` | 业务方 |
| **P1 存疑需人工** | `exit 2`(flag,如 judge 解析失败) | 业务方 |
| **P2 趋势** | 尚无(需多轮分布才谈趋势) | — |

- ✅ **每条告警可定位**:stderr 结构化日志带 `trace_id`/`span_id`;下钻 `eval-gate trace --run <id>`。
- ✅ **避免疲劳**:门是**跑一次出一次结果**,不存在"告警轰炸";去重/抑制**无对象**。
- ⛔ **响应时限 / 值班体系 / 通知通道(钉钉/邮件/IM)**:**无此项** —— 无值班主体(单人)、无外部受众。
  触发:出现第一个外部使用者,或门被接入**他人的 CI** 且需要响应时限(`DEC-014 §3 U3`)。
