# 参考 · 模块设计要点速查

> 各独立模块的定位、关键设计点、接口、指标。详细版见 workflow 知识库 `05-独立模块工作流/`(含「落地参考」章节与来源链接)。

## 1. 任务管理
- 职责:请求分解(Plan)、调度(Orchestration)、优先级、暂停/恢复、超时重试。
- 状态机:`pending→planning→executing→reviewing→completed/failed`。
- 要点:优先级队列防饥饿;幂等重试防重复副作用;token 预算防循环失控。
- 指标:L2 任务完成率、平均步数、重试率。

## 2. 上下文管理
- 职责:会话上下文 + 跨会话上下文;裁剪/压缩控制 token。
- 要点:保留最近 N 轮;超出部分摘要压缩;关键信息(任务目标/用户身份/约束)永不裁剪;Checkpointer 持久化支持断点续传。
- 指标:L2 截断率、压缩触发率;成本 token/请求。

## 3. 记忆模块
- 三分类:工作记忆(任务状态)、情节记忆(历史对话/执行记录)、语义记忆(知识库 RAG)。
- 要点:读写时机三问(何时写/何时检/如何更新);向量索引 IVFFlat/HNSW;遗忘曲线/新鲜度衰减;高频记忆 Redis 缓存;多租户隔离。
- 指标:L2 检索命中率、写入成功率;检索 P95、缓存命中率。

## 4. RAG 检索增强
- 管线:embed+BM25(并行)→ RRF 融合(k=60)→ 重排(top-50→top-5/20)→ 注入上下文。
- 要点:BM25 与向量必须同语料块集;分块 512 token + 50 重叠;元数据过滤;重排降级(交叉编码器 50–300ms,仅当评估证明收益);防幻觉双门控。
- 指标:Recall@5(混合+重排 ≈0.84)、MRR(≈0.73)、nDCG@20、忠实度(Ragas ≥0.85)。

## 5. Agent 路由(Router)
- 职责:请求 → 匹配处理单元;复杂度分层路由、模型路由、租户路由、降级路由。
- 要点:路由规则链(缓存→规则引擎→小模型→Agent→大模型);路由决策可回溯(可解释);降级链(主模型→备用→FAQ);循环检测熔断。
- 指标:路由 P99、路由正确率、降级触发率、缓存命中率。

## 6. 子 Agent 与多 Agent 编排
- 职责:Master 拆解调度,子 Agent 专精执行;协作协议。
- 模式:串行流水线 / 并行扇出 / 主从调度。
- 要点:单一 typed state 消除顺序竞态;消息协议版本化;共享记忆黑板;冲突仲裁(投票/置信度加权/上报);每子 Agent 明确能力边界。
- 指标:L2 子任务完成率、并行效率(加速比)。

## 7. 沙箱与安全执行
- 铁律:**绝不在宿主进程执行 LLM 代码**;生产用 **VM 级隔离**(Firecracker 微 VM),Docker 共享内核不足。
- 要点:沙箱默认临时、超时自毁;出口网络默认阻断、白名单放行;最小权限(只读默认、DB 表级授权、限流);审计「输入→思考→调用→结果→解读」全链。
- 落地:E2B(云)/ CubeSandbox(自托管,与 E2B 协议兼容);「沙箱合同」预定义命令/目录/网络/依赖边界。

## 8. 自愈策略(Self-Healing)
- 恢复矩阵:模型超时→重试退避→备用模型;工具失败→重试/跳过/等价工具;输出不合规→反射修正→人工;长任务中断→断点续传;连续失败→熔断告警。
- 要点:**护栏应修复而非仅拒绝**(evaluate-rewrite-reevaluate 收敛 96.9% vs 阻塞重试 49.1%);单步重试+检查点,绝不整段重跑;时序行为检测(重试风暴/卡死/循环推理/预算失控)。
- 指标:L2 自愈触发率、自愈成功率、MTTR。

## 9. 时序控制
- 机制:超时 / 重试(指数退避)/ 降级 / 熔断 / 并发背压。
- 熔断器:`闭合→(失败超阈值)→打开→(冷却)→半开→(成功)→闭合`。
- 要点:参数可配置可观测;非幂等操作不自动重试;超时分级(工具<模型<任务)。

## 10. 工具注册与 MCP
- 职责:统一注册/发现/调用工具;权限绑定;MCP 协议。
- 要点:**5–15 工具/服务器**(超出拆分,工具定义占上下文);动作命名(create_issue);`outputSchema`+`structuredContent`;校验错误走 `isError:true`(LLM 可见自校正);凭证放环境变量;工具即契约(变更走契约测试)。
- 指标:L2 工具调用准确率、成功率。

## 11. 全链路追踪与观测
- 职责:唯一 trace_id 贯穿全链路;结构化日志;Trace 可视化。
- 要点:OpenInference/OpenTelemetry GenAI 语义约定(span kind:CHAIN/LLM/RETRIEVER/TOOL/AGENT/EMBEDDING);日志字段规范(时间/模块/trace_id/action/入出参脱敏/耗时/status/tags);观测左移;采样保留长尾错误。
- 落地:LangSmith / Arize Phoenix / Langfuse;混合架构 OpenInference 埋点→OTLP→后端+数仓落存。

## 12. 提示工程与模型路由
- 职责:Prompt 版本管理、模型路由网关、评估驱动。
- 要点:提示即代码(Git 版本管理、A/B);按租户/流量灰度切流、秒级回滚;成本分层路由;评估集回归门禁;模型替换先在评估集离线对比。
- 指标:模型延迟 P95、Token/成本、评估集准确率、回滚时长(秒级)。

## 13. 评估与测试
- 评估集:真实案例 + 边界/对抗/拒答 + 历史事故;三类标注(意图/理想工具序列/标准答案);版本化同库。
- 分层测试:单元 → 集成 → 系统级 → 压测 → 混沌注入。
- 关键纪律:先定阈值再看结果;**统计回归**(A/B 各跑 50 次,p-value/效应量);版本化一切(Prompt/模型/数据集/评测器);污染控制;失败即补 case。
- 工具:DeepEval / Promptfoo / agent-eval / MLflow GenAI / Ragas。

## 14. 监控告警与仪表盘
- 三层指标:L1 系统(延迟/QPS/错误率/资源/Token 成本)、L2 代理逻辑(完成率/工具准确率/自愈率/步数)、L3 业务(介入率/CSAT/处理时间/FTE)。
- 要点:三层联动预警(L1 劣化→预警 L2→预警 L3);告警分级(P0/P1/P2);每条告警可定位 trace_id;版本可比支撑灰度对比。
