# 参考 · 12 步详细展开

> SKILL.md 的详细版。按步骤列出核心动作、关键细节、设计注入、产出物。源:workflow 知识库 `00-总览/00-全链路工作流-归档-v1.0.md` 第三节。

## 步骤 1 · 找到企业痛点,解析业务流程,解决方案
- 发现真实痛点:现场观察、数据埋点、员工访谈;定位「重复劳动最多、决策链条最长、人为错误最频繁」环节。**不依赖客户口头描述**。
- 业务流程还原:BPMN 流程图,标注节点输入/输出/决策规则/耗时/依赖系统。
- 拆解 AI 可替代/增强环节:
  | 环节 | 方案 |
  |------|------|
  | 信息检索 | RAG |
  | 规则判断 | 规则引擎 + 小模型 |
  | 多步规划 | Agent |
  | 复杂推理 | 调用大模型 |
- 注入:数据分级与隐私标注、人机协作模式、用户期望管理、法律合规需求。
- 产出:《痛点分析报告》《业务流程图(AS-IS)》《AI 可行性评估表》

## 步骤 2 · 分析、梳理、总结,策略与方案
- ROI 预判:节省人力/时间成本 vs 开发维护成本。
- 用例定义:输入(自然语言/结构化)、输出(回答/动作/报告)、成功标准(准确率/完成率/满意度)。
- 技术选型:模型(闭源/开源、参数规模)、框架(LangGraph/CrewAI/AutoGen/Claude SDK)、向量库(Chroma/pgvector/Milvus)、部署(云端/本地/混合)。
- 风险与约束:数据隐私、合规(GDPR)、安全(防注入)、延迟要求。
- 注入:成本分层与 ROI 挂钩、供应链选型评估。
- 产出:《技术方案设计书》《风险评估报告》《预算与时间估算》

> 门禁:进入步骤 3 前做「仿真与 Walk-through」。

## 步骤 3 · 设计整体系统架构蓝图
- 七层架构:
  1. 接入层:统一 API 网关(认证、限流、路由)
  2. 调度层:任务规划器(Plan-and-Execute)、Agent 路由器
  3. 执行层:多子 Agent(工具集、记忆、知识库)
  4. 记忆层:短期(滑动窗口/Checkpointer)、长期(向量存储)
  5. 工具层:统一工具注册中心(MCP 协议)
  6. 数据层:知识库、日志库、评估数据
  7. 安全/审计层:输入输出过滤、敏感信息脱敏
- 注入:灾备降级链与状态持久化、多租户隔离、合规审计框架。
- 产出:《系统架构图(C4 模型)》《组件职责说明》《数据流图》

## 步骤 4 · 设计完整的 Agent 架构(任务/上下文/记忆)
- 任务管理:分解(Plan)、调度(Orchestration)、优先级、暂停/恢复、超时重试;状态机 `pending→planning→executing→reviewing→completed/failed`。
- 上下文管理:当前会话(消息/工具历史)、跨会话(偏好/行为摘要)、裁剪策略(保留最近 N 轮、自动压缩)。
- 记忆模块:工作记忆(任务状态)、情节记忆(历史对话/执行记录)、语义记忆(知识库 RAG);读写策略(何时写/何时检/如何更新)。
- 注入:评估数据集规划、多 Agent 消息协议与仲裁、决策链与置信度。
- 产出:《Agent 内部状态设计》《记忆模块数据模型》《任务调度算法伪代码》

## 步骤 5 · 各模块细化设计
- 规划器:LangGraph 图结构 / Pydantic 结构化输出。
- 执行器:调用子 Agent/工具,并行/串行。
- 工具:输入输出 Schema、错误处理、重试策略。
- 记忆存储:表结构、向量索引(IVFFlat/HNSW)。
- 检查点(Checkpoint):任务中断恢复。
- 产出:《各模块详细设计文档》(类图、接口定义、异常处理策略)

## 步骤 6 · 撰写代码(前后端严格分离)
- **前端**:极简——一个对话框、一个发送按钮、展示结果;只负责发起请求、显示状态、流式展示输出;不含业务逻辑/路由/多 Agent 协作。
- **运营后台(Agent Console)**:面向运营/客服的后台——知识库管理(版本/灰度)、Prompt 与策略配置、会话监控与人工接管、数据看板。前端极简,后台完整,两者都不得耦合 Agent 内部逻辑。
- **后端**(全部复杂逻辑):Router、Master Agent(调度)、Sub-Agent(任务)、Sandbox(安全执行)、Self-Healing(异常恢复);时序控制(超时/重试/降级/熔断);全链路追踪(每请求唯一 trace_id 贯穿所有模块)。
- 工程纪律:接口契约先行(OpenAPI/protobuf + 契约测试);Mock 工具桩;观测左移(首个 Agent 运行即 OpenTelemetry + 本地 Jaeger)。
- 产出:《后端代码库》《前端代码库》《API 文档》《部署配置》

## 步骤 7 · 存储策略(全链路追踪/日志/向量/记忆)
- 日志:结构化 JSON(时间、模块、输入、输出、耗时、trace_id)。
- 追踪:OpenTelemetry → Jaeger / SkyWalking。
- 向量库:文档块、历史对话摘要、用户记忆。
- 记忆缓存:高频记忆 Redis,减少检索延迟。
- 备份:定期备份向量库和数据库。
- 产出:《数据存储设计》《日志字段规范》《备份策略文档》

## 步骤 8 · 各模块测试、验证、压测、性能指标
- 单元测试:每个函数/类覆盖正常+异常路径。
- 集成测试:模块接口、工具调用、记忆读写。
- 压测:Locust 模拟并发;QPS、P95/P99、错误率;CPU/内存/GPU;覆盖率、压测曲线、瓶颈分析。
- **红队安全测试**:越权查询他人数据、提示注入绕过、敏感信息诱取等攻击必须为零。
- 产出:《单元测试报告》《集成测试报告》《压测报告》《红队安全测试报告》

## 步骤 9 · 系统级全链路测试与量化指标
- 模拟真实流量模式(如一天业务流量)端到端测试。
- 验证完整链路:任务规划→执行→记忆读写→工具调用→结果返回。
- **回放测试**:用历史真实对话驱动 Agent,对比「Agent 会答什么 vs 人工答了什么」,发现系统性缺陷。
- 监控:成功率、平均耗时、P99、资源峰值;报告含环境/数据量/结果/对比基线。
- 产出:《系统端到端测试报告》《性能基准数据》

## 步骤 10 · 稳定性与鲁棒性优化
- 容错:模型不可用→降级备用模型;工具失败→重试/跳过;超时机制、熔断器。
- 自愈(Self-Healing):执行失败自动回滚或走替代路径;断点续传。
- 压测对比:优化前后延迟/吞吐/错误率。
- 混沌注入(Chaos Engineering):模拟网络延迟、服务宕机,观察系统行为。
- 产出:《鲁棒性优化报告》《故障场景应对手册》

## 步骤 11 · 量化数据、性能优化、监控机制、投放测试
- 监控面板:Grafana——QPS、延迟分布、错误率、Token 消耗、成本。
- 业务指标:用户满意度(反馈)、任务完成率、平均会话时长。
- 实时告警:超阈值钉钉/邮件通知。
- **投放节奏:影子模式(Shadow)→ 内测 → 灰度(先 10%)→ 全量**;先旁路运行收集对比数据,再灰度,任一层指标劣化即回滚。
- **人工接管 SOP**:Agent 转人工时带上下文会话卡片(意图/已确认信息/置信度/决策链)给客服,接管后打标签闭环。
- 数据追踪:记录用户行为、分析使用模式、发现优化点。
- 注入:分层健康度仪表盘(L1/L2/L3)、金丝雀发布、数据飞轮。
- 产出:《监控面板配置》《灰度发布报告》《初期使用数据报告》

## 步骤 12 · 日常维护与持续改进
- 日志审查:每日扫描高频异常。
- Trace 分析:抽样查看典型链路,识别性能瓶颈/逻辑错误。
- 用户反馈:建通道、定期归类、驱动迭代。
- 模型更新:更强/更便宜模型发布时评估替换。
- 知识库更新:补充新文档、清理过期信息。
- 注入:AI 辅助运维(异常聚类、Trace 回放诊断、知识库半自动更新)。
- **北极星指标**:设一个统领性业务指标(如「自动解决率」),把 L1/L2/L3 串起来,技术劣化最终反映到北极星,便于管理层对齐。
- 产出:《运维日报》《周度优化建议》《版本迭代计划》

## 执行节奏
- 步骤 1–2 必须先行;3–8 可部分并行;9–12 按序收尾。
- 推荐 MVP 先行(选一个端到端最小场景跑通 1–12 微循环),再横向扩展。
