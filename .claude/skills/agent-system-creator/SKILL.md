# Agent System Creator

把一个「从企业业务痛点出发,端到端创建一个**可生产、可信任、可进化**的 Agent 系统」的完整工作流,变成一套**可直接执行**的方法。你用它产出:业务诊断 → 策略方案 → 分层架构蓝图 → Agent 内核与各模块设计 → 前后端分离实现 → 存储与可观测 → 测试验证 → 稳定性加固 → 上线运营 → 持续优化。

## 核心心智模型(为什么这样做)

- **项目失败的第一根因不是技术,而是解决了一个不存在的问题**。所以永远从「真痛点」开始,用现场观察、数据埋点、员工访谈验证,而不是听客户口头描述。
- **双轨结构**:纵向「阶段推进」(步骤 1→12)+ 横向「设计原则」(安全、成本、信任、隔离等,每一步都要兼顾)。治理性内容不要做成独立步骤,要作为贯穿性约束。
- **目标是让 Agent 系统在企业里长期存活并产生价值**,不是「跑通 demo」。因此指标必须分层(L1 系统 / L2 代理逻辑 / L3 业务),技术指标劣化要能预警业务指标受损。

## 工作流总览:6 阶段 × 12 步

| 阶段 | 步骤 | 主题 |
|------|------|------|
| 一 需求与战略 | 1 | 找到企业痛点,解析业务流程,解决方案 |
| | 2 | 分析、梳理、总结,策略与方案 |
| 二 架构设计 | 3 | 设计整体系统架构蓝图 |
| | 4 | 设计完整的 Agent 架构(任务/上下文/记忆) |
| | 5 | 为每个模块单独设计架构、框架、执行策略 |
| 三 工程实现 | 6 | 撰写代码(前端与后端严格分离) |
| | 7 | 全链路追踪、日志、向量库、记忆存储策略 |
| 四 测试验证 | 8 | 各模块测试、验证、压测、性能指标 |
| | 9 | 完整系统级全链路测试、量化指标、数据报告 |
| 五 稳定性 | 10 | 稳定性、鲁棒性优化策略,压测对比报告 |
| 六 上线运营 | 11 | 量化数据、性能优化、监控机制、投放观测 |
| | 12 | 日常维护、日志/Trace 追踪、观测优化、bug 修复 |

执行节奏:步骤 1–2 必须先行;3–8 可部分并行;9–12 按序收尾。推荐 **MVP 先行、迭代式交付**(见「执行纪律」)。

## 分阶段执行

### 阶段一 · 需求与战略(步骤 1–2)

**步骤 1 找到痛点**:不依赖口头描述;用现场观察、数据埋点、员工访谈,定位「重复劳动最多、决策链条最长、人为错误最频繁」的环节;画 BPMN 流程图(标注输入/输出/决策规则/耗时/依赖);按环节选方案——信息检索→RAG、规则判断→规则引擎+小模型、多步规划→Agent、复杂推理→大模型。产出:《痛点分析报告》《业务流程图(AS-IS)》《AI 可行性评估表》。

**步骤 2 策略方案**:ROI 预判(节省成本 vs 开发维护成本);定义用例(输入/输出/成功标准);技术选型(模型、框架、向量库、部署方式);列风险与约束(隐私、合规、注入、延迟)。产出:《技术方案设计书》《风险评估报告》《预算与时间估算》。

> **门禁**:进入架构前,先做「仿真与 Walk-through」——纸面推演 Agent 处理典型用例的思考-行动序列,提前暴露上下文溢出、工具时序错误、记忆检索不准。

### 阶段二 · 架构设计(步骤 3–5)

**步骤 3 整体蓝图**——七层架构:接入层(API 网关:认证/限流/路由)、调度层(任务规划器 + Agent 路由器)、执行层(多子 Agent)、记忆层(短期滑动窗口/Checkpointer + 长期向量存储)、工具层(统一工具注册中心/MCP)、数据层(知识库/日志/评估)、安全审计层(输入输出过滤/脱敏)。产出:《系统架构图(C4)》《组件职责说明》《数据流图》。

**步骤 4 Agent 内核**:
- 任务管理:分解(Plan)、调度、优先级、暂停/恢复、超时重试;状态机 `pending→planning→executing→reviewing→completed/failed`。
- 上下文管理:会话上下文 + 跨会话上下文;裁剪策略(保留最近 N 轮、自动压缩)。
- 记忆模块:工作记忆 / 情节记忆 / 语义记忆(RAG);明确何时写、何时检、如何更新。
- 产出:《Agent 内部状态设计》《记忆模块数据模型》《任务调度算法伪代码》。

**步骤 5 模块细化**:规划器(LangGraph 图或 Pydantic 结构化输出)、执行器(并行/串行)、工具(Schema/错误/重试)、记忆存储(表结构/向量索引 IVFFlat 或 HNSW)、检查点(中断恢复)。产出:《各模块详细设计文档》(类图/接口/异常处理)。

### 阶段三 · 工程实现(步骤 6–7)

**步骤 6 撰写代码(前后端严格分离)**:
- 前端只保留一个简洁统一入口(对话框+发送+流式展示),**不含业务逻辑**。
- **运营后台(Agent Console)**:另建面向运营/客服的后台——知识库管理(新增/编辑/版本/灰度)、Prompt 与策略配置、会话监控与人工接管、数据看板。前端(用户入口)极简,后台(运营工具)完整,两者都不得耦合 Agent 内部逻辑。
- 后端实现全部复杂逻辑:Router、Master Agent、Sub-Agent、Sandbox、Self-Healing、时序控制(超时/重试/降级/熔断)、全链路追踪(每请求唯一 trace_id)。
- 同步执行:接口契约先行(OpenAPI/protobuf + 契约测试)、Mock 工具桩、**观测左移**(首个 Agent 运行即植入 OpenTelemetry)。
- 产出:《后端代码库》《前端代码库》《API 文档》《部署配置》。

**步骤 7 存储策略**:结构化日志(JSON:时间/模块/输入/输出/耗时/trace_id)、OpenTelemetry→Jaeger/SkyWalking、向量库(文档块/对话摘要/用户记忆)、高频记忆 Redis 缓存、定期备份。产出:《数据存储设计》《日志字段规范》《备份策略文档》。

### 阶段四 · 测试验证(步骤 8–9)

**步骤 8 模块测试**:单元测试(正常+异常路径)、集成测试(接口/工具/记忆读写)、压测(Locust:QPS/P95-P99/错误率/CPU-内存-GPU)、报告(覆盖率/压测曲线/瓶颈分析)。**红队安全测试**:越权查询他人数据、提示注入绕过、敏感信息诱取等攻击必须为零。产出:《单元测试报告》《集成测试报告》《压测报告》《红队安全测试报告》。

**步骤 9 系统级测试**:模拟真实流量模式做端到端测试;验证「任务规划→执行→记忆读写→工具调用→结果返回」全链路;**回放测试**——用历史真实对话驱动 Agent,对比「Agent 会答什么 vs 人工答了什么」,发现系统性缺陷;监控成功率/平均耗时/P99/资源峰值。产出:《系统端到端测试报告》《性能基准数据》。

### 阶段五 · 稳定性与鲁棒性(步骤 10)

- 容错设计:模型不可用→降级备用模型;工具失败→重试/跳过;超时机制、熔断器。
- 自愈(Self-Healing):执行失败自动回滚或走替代路径;断点续传。
- 异常注入测试(Chaos Engineering):模拟网络延迟、服务宕机。
- 压测对比:优化前后延迟/吞吐/错误率,用数据证明。产出:《鲁棒性优化报告》《故障场景应对手册》。

### 阶段六 · 上线运营与持续改进(步骤 11–12)

**步骤 11 投放**:Grafana 监控(QPS/延迟分布/错误率/Token/成本);业务指标(满意度/完成率/会话时长);实时告警(钉钉/邮件);数据追踪。**投放节奏:影子模式(Shadow)→ 内测 → 灰度(10%→逐步扩大)→ 全量**——先旁路运行收集对比数据,再灰度,任一层指标劣化即回滚。**人工接管 SOP**:Agent 触发转人工时,带上下文会话卡片(意图/已确认信息/置信度/决策链)给客服,客服接管后打标签闭环。产出:《监控面板配置》《灰度发布报告》《初期使用数据报告》。

**步骤 12 维护**:每日日志审查、定期 Trace 分析、用户反馈归类、模型/知识库更新。引入 AI 辅助运维(异常聚类、Trace 回放诊断)。**运维反馈 = 下一轮步骤 1 的输入,形成闭环**。产出:《运维日报》《周度优化建议》《版本迭代计划》。

**北极星指标**:为整个系统设定一个统领性业务指标(如「自动解决率」),把 L1/L2/L3 串起来——技术劣化最终都要能反映到北极星上,便于向管理层汇报对齐。

## 贯穿性设计原则(每一步都自检)

以下原则不是附加步骤,而是渗透到每个决策的约束:

1. **安全合规伦理**:数据分级脱敏;防提示注入/越狱/工具滥用;权限最小化;关键操作人在环中;审计记录「谁/何时/为何」;法律与 IP(输出合规过滤、授权边界、不可篡改审计日志)。
2. **成本与 ROI**:成本分层(缓存→小模型→大模型);token 预算与循环熔断;技术指标与痛点基线挂钩(FTE/CSAT)。
3. **多 Agent 协作与人机协同**:消息协议 + 共享黑板 + 任务依赖图;冲突仲裁(投票/置信度加权/上报 Master);人机三模式(辅助/增强/自动化);显性反馈通道。
4. **信任、进化与隔离**:提示即代码(纳入 Git、A/B、灰度回滚);数据飞轮(反馈回流为训练样本);可解释性(决策链卡片 + 置信度);灾备(降级链 + 断点续传);供应链(适配器层 + 依赖监控);用户心智(能力声明 + 渐进暴露);多租户隔离(租户 ID 全链路透传)。

| 模块 | 一句话职责 | 关键设计点 |

| 子 Agent 编排 | Master 拆解调度 | 串行/并行/主从、共享黑板、仲裁 |

| 自愈策略 | 失败自动恢复 | 重试/回滚/替代路径、断点续传、反射 |
| 时序控制 | 超时/重试/熔断 | 指数退避、幂等、背压 |
| 工具注册/MCP | 统一工具接入 | 5–15 工具/服务器、Schema、权限绑定 |
| 追踪观测 | 全链路可见 | trace_id、OpenTelemetry、结构化日志 |
| 提示/模型路由 | 模型与提示管理 | 版本化、灰度、秒级回滚、成本分层 |
| 评估测试 | 质量门禁 | 版本化评估集、统计回归、发布门禁 |

## 执行纪律

- **MVP 先行**:选一个端到端最小场景(如单一工单自动处理),快速跑通 1–12 微循环,再横向扩展。选型标准:① 覆盖核心价值(痛点最痛、ROI 最高);② 依赖最少(不阻塞于外部系统);③ 链路完整(能验证记忆/工具/路由/追踪);④ 可量化(有明确成功标准)。
- **仿真门**:写码前纸面推演思考-行动序列,暴露三类高成本问题(上下文溢出/工具时序/记忆检索)。
- **契约优先**:前后端与模块间先定义接口契约并做契约测试;真实 API 前用 Mock 桩。
- **观测左移**:第一个 Agent 运行即有 Trace,不要等存储阶段才补。
- **CI/CD for Agent**:每次改 Prompt/工具/记忆策略自动跑评估集,低于阈值阻断发布;金丝雀灰度,秒级回滚。
- **分层指标**:L1 系统(延迟/QPS/错误率)、L2 代理逻辑(完成率/工具准确率/自愈率/步数)、L3 业务(介入率/CSAT/处理时间/FTE),三层联动预警。
- **先限制后放开**:从最受限的护栏开始,确认稳定后再逐步放开能力。

## 交付物与量化指标

每个阶段必须产出对应交付物(见上),并以指标验收:

| 层 | 指标 | 参考基线 |
|----|------|----------|
| L1 系统 | 延迟 P50/P95/P99、QPS、错误率、资源 | 压测基线;P99 达标 |
| L2 代理 | 任务完成率、工具准确率、自愈触发率、平均步数 | 评估集回归;低于阈值阻断 |
| L3 业务 | 人工介入率、CSAT、处理时间缩短、FTE 节省 | 对标步骤 1 痛点基线 |

## 输出格式(始终遵循)

每次使用本技能,最终交付应包含以下结构:

1. **一页总览**:痛点 → 方案 → 阶段路线图。
2. **阶段交付**:按 6 阶段列出步骤、门禁、产出物、指标。
3. **模块清单**:需设计的模块 + 每个模块的关键设计点与接口。
4. **风险与原则对照**:横切原则落地清单(勾选)。
5. **实施计划**:MVP 场景、迭代节奏、验收标准、上线与优化节奏。
