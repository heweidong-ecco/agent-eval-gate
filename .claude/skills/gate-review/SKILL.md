# gate-review · B 阶段门退出检查

作用:防止"没到验收就进下一阶段"。门禁表以 **B 知识库 `04-分阶段工作流/04-阶段1~6`** 各阶段卡的「本阶段门禁」为准,不以"感觉做完了"判过。

## 输入
- 阶段号(1~6)+ 该阶段产出物位置(如 `需求基线.md`/`总纲.md`/PR)。
- B 知识库绝对路径:默认读项目 `CLAUDE.md` 里的 `/Users/heweidong/Desktop/Product/product-agent-dev-os/知识库-Agent-System`;读不到则问用户。

## 步骤
1. 读 B 阶段卡 `<B>/04-分阶段工作流/04-阶段<X>-*.md`,取出「本阶段门禁」清单(和产出物、应注入原则)。
2. 逐条对照产出物,给 `PASS` / `MISS` / `⚠️ 存疑`,并附证据位置。
3. **北极星 / L1/L2/L3 检查**:本阶段产出是否已挂或更新了分层指标口径(对照项目 `总纲.md` §4 + `eval/阈值.md`);北极星是否仍可统领 L1/L2/L3。阶段 4/5/6 相关门额外要求:评估回归结果、L1/L2 基线、压测对比报告是否带数据。
4. MISS/存疑项给最小补救建议与下一步。
5. 输出结论:可进入阶段 N+1 / 暂不可(列出缺口)。
6. 若涉及发布/上线类门(阶段5/6),额外提示:CI(含 eval-gate)是否绿、回滚是否演练、灰度数据是否带版本可比、有无未决 Critical。

## 输出格式(紧凑)
```
Gate 阶段<X> 评审
- B 门禁来源:<04-阶段X 文件路径>
- 产出物:<清单/位置>
- 逐条:✓/✗ 项(附证据)
- 北极星/L1/L2/L3:挂钩 OK / 缺口 <…>
- 结论:PASS / BLOCK —— 缺口 <…> / 下一步 <…>
```

## 纪律
- 以 B 阶段卡门禁为准,不以"感觉做完了"判过。
- 缺口不静默吞;要么补、要么记 DEC 说明为何豁免(如非目标项需显式排除)。
- 阶段门通过 ≠ 发布门;发布前仍需 留痕-checks + eval-gate。
