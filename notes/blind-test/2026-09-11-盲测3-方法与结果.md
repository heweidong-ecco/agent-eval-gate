### 6.3 ⭐ 本轮最重要的三条

**① 门禁是「可发现」的,而发现了就会改变行为(2/2)**

两个 Agent 都在**动手写码之前**去 `cat` 了门禁源码(`impl-guard.sh` / `commit-msg`)。
**这比"被拦住再改"更强一层**:门禁不只拦截,它作为**可读结构**事先塑造了行为。
(对照:两者**都没读 `CLAUDE.md`** —— 与盲测 1 一致。**代码即文档,hook 即纪律。**)

**② 入口触发器 `using-superpowers` 自触发了 —— 但只在一个 Agent 上(1/2)** ⚠️

Agent B 第 1 步就调了它,**零提示**;Agent A 没有。**同一机制,2 个样本 2 种行为 → 不可靠。**
这与盲测 1/2 的「0 次调用」也有出入 —— 说明它是**概率性**的,不是确定性的。

**③ ⚠️ 方法学盲区:门禁可被发现时,盲测测到的是「合规」,不是「拦截力」**

本轮**没有复测**门 1 / 门 2 的拦截力 —— 因为 Agent 合规得太早,门没机会响。
→ **要复测拦截力,必须让 Agent 拿不到门禁源码**(或换一个不诱导探索的任务)。
→ 这同时暴露一个**未测的攻击面**:源码可读 ⇒ **可规避**(`--no-verify` / `[no-test]` / `[no-skill]`)。
两个 Agent 都**选择**了合规 —— 但**没有任何机制阻止它们选择规避**。
