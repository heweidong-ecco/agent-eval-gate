## 1. 「门的灾」是什么(先定义,再演练)

本仓是**结论入库、原始证据不入库**:

| 产物 | 在 git? | 说明 |
|---|---|---|
| `eval/runs/*.summary.md` | ✅ **在** | 脱敏摘要(9 份) |
| `eval/runs/*.trace.jsonl` | ❌ **不在**(`.gitignore:24`) | per-case 延迟/状态 —— **L1 基线的输入** |
| `eval/runs/*.local.json` | ❌ **不在** | 报告原文,**含被测答案原文**(刻意不入库) |
| `eval/l1_baseline.json`、`docs/reports/**` | ✅ 在 | 结论 |

⇒ **「门的灾」= 证据链丢失**:机器没了 ⇒ **L1 基线无法重算**、报告/复盘里引用的 trace 失效。

## 2. 首次演练(2026-09-13,补救**前**)

```
① 盘点
   git 跟踪的 eval/runs 文件 : 9   (脱敏 summary)
   仅在本地的 trace          : 38
   仅在本地的报告原文        : 48   (含被测答案原文 —— 刻意不入库)
③ 仅用 git 里的内容重算 → exit=3
   「未找到 trace: eval/runs/20260912-171456-f5c4a6ec.trace.jsonl」
```

**结论:MTTR = 不可用(无界)** —— 不是"恢复得慢",是"**根本恢复不了**"。
git 里只有脱敏 summary,**重建不出 per-case 的延迟与状态**。

## 3. 补救(按 `DEC-014 §4.1` 的归档纪律)

新增 `tools/archive_evidence.py`:把**被报告/复盘引用到的** run 抽成
`eval/runs/<run_id>.spans.jsonl`(**进 git**)。
名字刻意**不叫** `.trace.jsonl`,所以不会被 `.gitignore` 吃掉;恢复时改回即可。

**脱敏是硬约束**:只留结构字段 + 白名单 attributes;`answer` / `input` / `output` / `error.msg`
一律丢弃(它们可能含被测答案原文)。**测试含两条**:
① 摘录不得出现白名单外字段;② **往返校验** —— 摘录改名回 `.trace.jsonl` 后统计**逐字一致**。

已归档基线那 5 轮(`20260912-171456` / `-180913` / `-182720` / `204217` / `204233`)。

## 4. 复演(补救**后**)

③ 从恢复源重算 → exit=0 · 耗时 **1s**

## 5. MTTR

| | 值 |
|---|---|
| **补救前** | **不可用(无界)** —— 首测直接重算 exit 3,证据不可恢复 |
| **补救后(本次实测)** | **≈ 1 秒**(纯恢复段:从 `git show HEAD:…spans.jsonl` 取归档 + 重算) |

> **"被引用的证据"= 可恢复;"没被引用的"= 丢了就丢了。**
