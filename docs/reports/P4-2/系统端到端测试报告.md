## 4. ⚠️ 本轮最重要的发现:**轮间不稳定(近 2×),原因未查明**

**观测**:同为被测 `f2dad78`、同为 48 条集:

| run | `sut.call` p50 | mean | 合计 |
|---|---|---|---|
| `20260912-171456-f5c4a6ec` | **3537 ms** | 3895 ms | **187.0 s** |
| `20260912-180913-432c0daa` | 1594 ms | 2015 ms | 96.7 s |
| `20260912-182720-ee9c3495` | 1673 ms | 2016 ms | 96.8 s |

**是系统性差异,不是离群**:逐 case 配对比较(171456 vs 182720)倍数的**中位数 = 0.46**,
个别 case 快 5–6×(如 case 34:4000 ms → 581 ms)。后两轮彼此则高度一致。

**已排除的解释**:
- ❌ **模型网关波动** —— 同期 `judge.grade`(同网关、同模型 `deepseek-v4-flash`)p50 三轮分别 **1583 / 1637 / 1630 ms**,
  **稳定**;而 `sut.call` 翻倍 ⇒ 差异在**被测自身路径**,不在共享模型端点。
- ❌ **语料更多导致更慢** —— 171456 是 **70 篇**,比后两轮**更少**却更慢。

**候选原因(⚠️ 均为未验证假设,不得当结论引用)**:① 被测侧冷启动 / 索引或 BM25 缓存未预热;
② 被测上游输入长度分布不同;③ 该时段机器或容器资源竞争。

**它为什么要紧(直接影响未决项)**:
`eval/runs/20260912-180913-432c0daa.summary.md:79` 与 `182720` 的摘要都记着
「墙钟 176.3 / 171.7 s,距阈值 180 s 仅 2–5% 余量 —— 阈值 180 s 偏紧」。本轮结论是:
**问题不是"偏紧",而是这个量本身不稳** —— 同一条件下已实测到 **269.2 s**。
若把墙钟接成阈值/阻断项,会**误报**。

**建议(须业务方定夺,本节点不改阈值)**:
1. **不把墙钟接为阻断项**;若要设,先做 N 轮重复测其分布(属 `M2` 类工作,须报备预算);
2. 或改口径:只对 `sut.call` 的**分位数**设阈值,并接受其跨轮波动;
3. 无论哪种,**须单独 DEC + 签核**(现状:墙钟阈值尚未接线,故本发现不构成回归)。

## 4.5 ⚠️ 附带的硬发现:**在案的 L1 阈值已被真实数据越线,且从未接线**

L1 阈值**不是没有**,它挂在 `总纲.md` §4 与 `eval/阈值.md:25-30`,但标定于 **40 条**时代(R1b):

| 在案的 L1 阈值 | 文档记的"实测" | 本轮真实观测 | 判定 |
|---|---|---|---|
| 单轮评测墙钟 **< 180 s**(**40 条**) | 86.9 s | 171.7 / 176.3 / **269.2 s** | ❌ **一轮越线**;另两轮仅 2–5% 余量 |
| `sut.call` 中位 **< 3 s** | 916 ms | 1594 / 1673 / **3537 ms** | ❌ **一轮越线**(池化 p50 2364 ms 未越线) |
| `judge.grade` 中位 **< 5 s** | 1247 ms | 1583 / 1637 / 1630 ms | ✅ 未越线 |
| 错误率 **< 1 %** | 0 | 0 % | ✅ 未越线 |

**两个独立问题**:

1. **口径已过时** —— 阈值按 **40 条**标定,而评测集已是 **48 条**(+20% 用例)⇒ 墙钟口径本身就错配;
   且"实测 86.9 s"是 40 条时代的单点。
2. **从未接线** —— `eval/阈值.json` 的机读键只有 `l2_task_completion` / `redteam_zero` / `judge_human_agreement`,
   **没有任何 L1 键** ⇒ `runner.load_thresholds()` 不读它 ⇒ **越线不会有任何东西变红**。
   这与本项目此前修过的「阈值未接线」(`R2b 遗留①`)是**同一形状**,也与避坑库 `A5`(验证的假象)同族。

**建议(须业务方定夺;本节点不改口径、不改接线)**:
- **必须记 DEC**:① 重定标(按 48 条、按真实分布)或改口径;② 是否接线为阻断项。
- 在 DEC 前,**不得**把墙钟/延迟阈值当作"已生效的门" —— 它现在既不生效、又与真实数据冲突。
