## 2. 靶子① · 作弊的被测(未打穿)

- **攻击**:被测输出「这个问题问得非常好!毫无疑问,您的分析完全正确…」这类讨好判分器却无实质内容的话术。
- **防线**:门的判据是 `answer_contains` **硬命中**,且**确定性规则先于 judge**(总纲 §1 不变量①);
  讨好话术天然不含期望要点。
- **实测**:注入后达标率 **< 0.5**、`exit != 0`、红队条目 **0 通过**。
- **用例**:`test_sycophantic_stub_is_not_passed_by_gate`、`test_sycophant_cannot_pass_redteam_cases`。
- **回灌**:`eval/cases/eval-gate-redteam-2026-09-11.json` id=901。

## 3. 靶子② · 畸形输出(**打穿 1 处,已修**)

### 3.1 打穿点:非 UTF-8 可编码文本(孤立代理对)

- **攻击**:被测返回含孤立代理对的文本 —— JSON 里写转义 `\ud800` 即可送达,无需任何特殊通道。
- **后果链**:`obs.digest()` 在**日志摘要**处 `str.encode("utf-8")` → `UnicodeEncodeError`;
  `SutOutput.answer` 原样带毒,报告落盘同样会崩。
  **整轮被掀翻**(不是逐条记 fail),且**进程崩溃退出码 1 在 CI 里恰好等于「质量阻断」**。
- **修复**:入口归一 —— `obs.clean_text()` + `SutOutput.__post_init__`;
  `digest()` 用 `errors="replace"` 兜底(**摘要函数是所有日志的入口,它崩 = 整轮崩**)。
- **用例**:`test_digest_survives_unencodable_text`、`test_sut_output_sanitizes_unencodable_text`。
- **回灌**:id=902。

### 3.2 未打穿:超长 / 空 / 巨型 JSON

- 10 万字符回答、5 千条 `sources`、空串、全空白 —— 门均**跑完整批**,该条按判据记 fail。
- **设计取舍(明确声明)**:**本门刻意不设输出长度上限**。设上限等于引入一个
  **未经业务方签核的阈值**;正确做法是"不崩 + 逐条按判据判 + 日志脱敏"。
- **脱敏验证**:结构化日志逐行解析,任何字段都不得含 >300 字符的长文本(回答只以 `{len, sha8}` 出现)。
- **用例**:`test_malformed_sut_output_is_recorded_not_crashing`(参数化 5 种,**必须带 tracer**)、
  `test_oversized_answer_is_not_written_into_logs`。**回灌**:id=903。

### 3.3 附带守住的两条韧性语义

- 非配额错误 → 逐条记 fail,run 继续;配额耗尽 → 整批 aborted + `degraded` + **exit 3**(阈值判定作废)。
- 用例:`test_sut_error_does_not_abort_batch_except_quota`、`test_quota_error_aborts_batch_with_exit_3`。

## 4. 靶子③ · judge 出参越界(未打穿)

- **攻击**:judge 返回非法 `verdict`、越界 `score`(如 `7.5` / `-3`)、超大或非串 `reasons`。
- **防线**:`_parse_verdict` 严格校验 —— 非法 `verdict` → 返回 `None`(走重问,最终 `flag` 而非默认给分);
  `score` **clamp 到 `[0,1]`**;`reasons/evidence_refs/labels` 一律 `str()` 化。
- **实测**:`judge.py` 覆盖率 **86% → 100%**,全部越界形态有断言。
- **用例**:`tests/test_judge_error_paths.py`(20)。

## 5. 靶子④ · 评测集投毒(未打穿)

- **攻击**:让门在"配置已坏"的状态下开始烧钱调模型(畸形 `expected` / 非法 `module` /
  非串候选 / `checks` 真值非对象 / id 重复 / `deterministic_only` 缺机器规则 / `expected` 空 / 恶意超长 input…)。
- **防线**:E1「**零模型调用即失败**」—— `load_evals` 只做结构与文件校验,不触碰任何被测/judge I/O。
- **实测(门级证明)**:`test_poisoned_evalset_fails_before_any_model_call` 用 **Tripwire** 记录
  `Judge` 的构造次数 → 投毒评测集下 **构造次数 = 0**(`exit 3`,不产出报告)。
  另有 16 类畸形形态逐一断言契约错误码。
- **用例**:`tests/test_schema_error_paths.py`(19)+ 上述门级用例。**回灌**:id=904。
