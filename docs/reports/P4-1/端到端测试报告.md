```bash

  python -m eval_gate run --evals eval/mini_rag_qa.evals.json --mode good --offline --report-dir <dir>
```

### 3.2 阻断点与根因(证据链)

被测的 `/api/v1/rag/search` 在**查询改写**一步(`query_rewriter.py:99`)抛:

```
openai.PermissionDeniedError: Error code: 403
{'error': {'message': 'Free quota exhausted. ... disable the "use free tier only" mode ...',
           'type': 'AllocationQuota.FreeTierOnly'}}
```

根因**不是**被测的质量问题,而是**环境问题**,证据链如下:

| # | 证据 | 说明 |
|---|---|---|
| 1 | 直连被测所用的 **DashScope(阿里云百炼)key** → 返回 **403,报文与上逐字相同** | 该 key **免费额度已耗尽** |
| 2 | 被测 `.env` 里 `LLM_BASE_URL=https://api.deepseek.com`,但**容器内实际跑到 DashScope** | 配置未生效 |
| 3 | 镜像 `my-fixed-name-api` 构建于 **2026-07-01** | **早于** 2026-09-10 的 DeepSeek 迁移两个多月 |
| 4 | 镜像内 `/app/config.py` 与仓库 `api/config.py` **md5 不一致**,且镜像版 `grep -c LLM_BASE_URL` = **0** | 容器里是**旧代码**,回落到了 DashScope |
| 5 | 同一把 key / 同一 base_url / 同一模型名,从宿主机直连 judge → **HTTP 200** | 排除"key 整体失效";确认问题在**容器里的旧代码** |

**附带发现(被测侧,与本门无关)**:`docker run --env-file` **不剥离行内 `#` 注释** ——
被测 `.env` 的 `LLM_MODEL_FAST=deepseek-v4-flash   # 轻量角色:…` 被整行当成值,
模型名成了 `"deepseek-v4-flash   # 轻量角色:…"`(网关据此返回 400)。已用
`-e LLM_MODEL_FAST=deepseek-v4-flash` 覆盖修正,随后才暴露出上面真正的额度阻断。

### 3.3 未跑声明(口径)

- **未跑的部分**:真实被测 × 真 judge 的一轮完整评测(`eval/fastapi_rag_golden.evals.json`,40 条)。
- **为什么**:被测侧第三方额度耗尽 + 容器镜像陈旧,**被测没有任何作答能力**;
  此时跑一轮得到的只会是 40 条"被测调用失败",**不是质量测量**(与 spec §8「外部依赖抖动导致的失败不得计入门自身错误率」同一原则)。
- **影响什么结论**:本节点**不能**给出"今天这一刻的门-真实链路基线";
  但 **L1/L2 的真实基线并非空白** —— 见 §4。
- **怎样才能跑**:① 给 DashScope 充值,或把被测 embedding/LLM 切到可用 provider;
  ② 重建镜像 `docker compose build api`(或按阶段3 方式用本机 venv 起被测,避开陈旧镜像)。
  两步齐备后,命令为:`EVAL_LIVE=1 python -m eval_gate run --evals eval/fastapi_rag_golden.evals.json --report-dir eval/runs`。
