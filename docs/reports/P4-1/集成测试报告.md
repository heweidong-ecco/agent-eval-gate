## 4. 「失败即补 case」的结构守卫

本节点新增失败集 **`eval/cases/eval-gate-redteam-2026-09-11.json`**(4 条),与既有
`eval/cases/fastapi-rag-2026-09-10.json`(6 条)一并由 `tests/test_failure_cases.py` 硬校验:

- 文件必须能被 `load_evals` 装载(失败集本身不能是坏的);
- **每条必须带** `regression.from_run` / `observed` / `root_cause` / `status`(缺根因即拒);
- `status ∈ {open, fixed, accepted}`。

命令:`pytest -q tests/test_failure_cases.py` → passed。

> ⚠️ 易漏点:红队用例**必须带 tracer** 才算走过生产路径 —— CLI 默认 `EVAL_TRACE=1`,
> 而 `digest()` 只在观测路径被调用。不带 tracer 会把"生产崩溃"漏测成通过(本轮实际踩过,见 `docs/复盘/2026-09-11-P4-1-过程错误.md` E2)。
