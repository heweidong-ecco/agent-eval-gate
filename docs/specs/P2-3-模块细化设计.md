## 6. 评估阈值与指标(变更即跑)
- 本节点**纯设计,未动 Prompt/代码/评估集** → 无 eval 回归触发。
- P3 起每落代码/改评估集 = 必跑 `eval` 回归(对照 `eval/阈值.md`);预期阈值先占位,阶段2 首样本(mini RAG-QA 或真实 37 golden)标定后回填。L1 成本目标(judge token/跑批延迟)以 P3 压测出基线。

## 7. 人在环中(HITL)
- 人机模式=增强:judge 出分,人终裁阈值与边界。
- 人工触点:`flag`/`conditional` → human review(exit 2);judge-人工一致率<阈值 → ⚠ 建议人工复核;红队命中 → 人确认是误报或放行前整改。

## 8. 失败处理与自愈
- 降级链(被测侧):真实 fastapi-rag 不可用/配额耗尽(`E_SUT_QUOTA`)→ run degraded 不假装全绿;开发态可切 snapshot/离线适配器(真实被测的导出快照)→ mini-rag-qa(自含)。judge 侧:单模型超时→重试→熔断并标 degraded;跨模型仅作参照,不改断言(分数不可比)。

## 9. 观测点
- 每次 run:run_id 贯穿;结构化日志(评测集版本/judge 模型/每 case 判定/成本 token);报告入 E7 基准库。trace 字段按 `observability/trace_id-规范.md`(阶段3 编码即接)。

## 10. 横切原则对照
- [x] 安全合规:红队走确定性(E3)、脱敏入库、密钥托管(E8)
- [x] 成本与 ROI:坏配置零调用、抽样/截断/并发上限/熔断(E5)、judge max_tokens(E4)
- [x] 人机协同:增强模式 + flag/human 出口(E7、阈值人终裁)
- [x] 信任进化与隔离:版本化一切、judge 模型防锁仓且跨模型不可比(DEC-002)、报告可回溯(E7)
