# Memory · 开发仓库记忆与知识沉淀规约

> **消歧(必读)**:本文件 = **开发仓库记忆**(项目锚/CLAUDE/决策留痕/知识沉淀,属于工程壳);**不是**被构建 Agent 系统的运行时记忆。B 的「记忆模块」(`知识库-Agent-System/05-独立模块工作流/05-模块-记忆模块-v1.0.md`)是被构建系统的运行时三类记忆(工作/情节/语义),设计它时去读 B 05-记忆模块,与本文件无关。两者同名异物,勿串(消歧表见 `README.md`)。
>
> **目标**:任何时刻中断,新会话凭「项目锚 + 文档」无缝接上;知识与决策进 git,不靠会话记忆。

## 一、仓储记忆三层

| 层 | 位置 | 放什么 | 谁维护 |
|---|---|---|---|
| 全局(你所有项目) | `~/.claude/CLAUDE.md` + 用户级 skills/settings | 通用纪律、skill 路由、常用命令、成本原则 | 你 |
| 项目锚 | 项目根 `CLAUDE.md` | 接续协议 + 当前指针(`分支\|阶段X-步骤Y\|模块:…\|L3基线:…\|北极星:…`,格式见 `RUNBOOK.md` §1.1) | 每节点更新 |
| 项目文档(事实层) | 仓库 `需求基线/总纲/ROADMAP/DEC/contracts/…` | 一切可被"事实"引用的内容 | 随 RUNBOOK 六阶段产生 |

## 二、事实纪律(防幻觉/防漂移)

- **单一事实源**:业务口径、技术/合规表述只准引用仓库内事实源(`需求基线.md`、`contracts/`、B 权威文件);AI 不凭空写。
- **决策留痕**:每个选型/边界决定 = 一份 DEC(`DEC-选型模板.md`);变更走"冲突先回总纲对齐再改"。
- **外部引用标注**:引用外部数据(调研/法规/竞品/价格)必须带来源 + 置信度 + "外部参考,非本公司事实";B `07-参考` 层为 2026-08-09 搜索,落地前复核。
- **不静默改**:改基线/契约/验收先讨论或记 DEC,再改。

## 三、决策留痕(DEC)

- 所有选型/默认值/结论进 `docs/decisions/DEC-<nnn>-<slug>.md`,编号递增;记录"为什么",可被新决策推翻(引 B 供应链原则"适配器抽象层",反悔成本挂 DEC 模板)。

## 四、知识沉淀(复盘/随时)

- 可复用件(模板/脚本/skill/提示词)→ 回 Kit 的 `scaffold/agent/` 或 `skills/`。
- 踩坑/方法论 → 每项目 `docs/notes/`,或升级到全局记忆。
- 复盘 → `docs/复盘/`,行动项进 issue/看板。
- **蒸馏 vs 源头**:知识库是源头档案、技能/模板是蒸馏可执行版——改源头后按 `知识库同步映射.md` 同步,避免两处漂移(B `README.md` §四)。

## 五、会话接续协议(每项目 CLAUDE.md 都写)

1. 读项目 `CLAUDE.md` → `ROADMAP.md`「当前指针」。
2. 找到 ▶ 或下一 ⬜ 节点 → 读其 spec/plan → 按 `RUNBOOK.md`(指 B 阶段卡/模块卡)继续。
3. 完成节点:改 ROADMAP 状态 + commit + 更新 CLAUDE 指针。
