# 知识库 ↔ Kit 同步映射 · 改 B 后同步什么、怎么重打包

> **用途**:B(`知识库-Agent-System/`)在本 Kit 是**权威(只增不改、版本化)**;它同时蒸馏出一份可执行技能 `agent-system-creator`(SKILL.md + references ×5 + evals)。本文件把 B 已固化的同步规则归纳成 **Kit 内维护约定**:改了 B 某层 → 同步哪个蒸馏件 → 如何重打包 `.skill`。
>
> 依据:B `README.md` §四「维护约定」+ B `agent-system-creator/skill命令行使用note.md`「同步更新策略」问答。**本文件不替代、只归纳**这两处;两者冲突以 B 原文为准。

## 0. 三个对象的定位(先分清)

| 对象 | 定位 | 位置 |
|---|---|---|
| 知识库 B | **源头档案**(详细、含版本与案例;只增不改) | `知识库-Agent-System/`(仓库根,B 权威目录) |
| 蒸馏技能 | **可执行版**(精简、便携、渐进式披露) | B 内 = `知识库-Agent-System/agent-system-creator/`;装进 Kit skills = `skills/agent-system-creator/`(**待 M2 迁入**,见 `02-增删映射表.md` §4-2) |
| `.skill` zip | **分发/安装格式**,不可直接执行(须指向源 SKILL.md) | 仅作对外分发产物 |

## 1. 改 B 哪一层 → 同步哪个蒸馏件

## 2. 同步决策分级

| 变更类型 | 例子 | 是否同步 | 同步到哪 |
|---|---|---|---|
| 结构性变更 | 新增步骤/改门禁/改输出格式 | ✅ 必须 | `SKILL.md` + 对应 reference |
| 新增通用可复用实践 | 某模块新增实施策略(如新重排手段) | ✅ 应该 | 对应模块在 references 的段落 |
| 新增具体工具/链接/指标基线 | 选新向量库、加参考链接 | ⚠️ 视情况 | `references/05-tooling.md`(若全局选型/链接) |
| 仅案例/版本化数据/细节数字 | 某客户案例指标、某版本修订记录 | ❌ 不需要 | 留在知识库,技能不承载 |

## 3. 便捷做法(最省事)

改完 B 某模块后,对 Claude 说一句:「**把这次 05-模块-记忆模块 的修改同步到技能**」。Claude 应:① 判断变更级别(上表);② 更新对应 reference 或 SKILL.md(蒸馏成精简版);③ 重新 zip 打包 `.skill`。见 B `skill命令行使用note.md` 末尾。

## 4. Kit 内重打包约定

- 打包命令示例(在 `知识库-Agent-System/agent-system-creator/` 的**父目录**执行,使 zip 内含 `agent-system-creator/` 顶层目录):
  ```bash
  cd 知识库-Agent-System
  zip -r ../dist/agent-system-creator.skill agent-system-creator
  ```
  (待核:分发目录 `dist/` 位置与是否纳入 git,由 Kit 拍板;`.skill` 本质 zip,不可直接执行。)
- 产物名保持 `agent-system-creator.skill`;改动 SKILL.md 或 references 后版本号按 B `README.md` §三语义化规则在文件头追加变更记录。

## 5. B 原始层与参考层特殊规则

- `01-原始资料/`:**只增不改**,新增搜索内容以 `-v1.x` 追加,不覆盖旧版;同步技能时属"细节数字"→ 通常不同步。
- `07-外部参考与落地/`:外部参考(2026-08-09 搜索),时效敏感;同步到 `references/05-tooling.md` 时**保留"落地前复核"标注**,不写成 Kit 断言。
