## 二、教训(下次可照做的规则)

1. **「跑通了」不是验证,「在测东西」才是。**
   E1 的产物有 N、有检出率、有 p 值,格式全对 —— 唯一的问题是那些数字没有意义。
   → **可操作化**:凡"重复 N 次"的实验,必须**断言重复之间确实不同**
   (取值多样性 / 种子不同 / 方差 > 0),否则 N 次的 N 是个装饰。

2. **测试必须走生产路径,尤其是"默认开着"的那部分。**
   E2 的根因:我按"最小调用"写测试,而生产默认会开观测。
   → **可操作化**:写测试前先问一句「生产默认配置是什么?我这个调用与它差在哪?」;
   差在关键开关上(观测/阈值/并发)时,测试按生产默认写。

3. **自洽的对账证明不了口径正确,要用外部锚点。**
   E3 里"实现 vs 自己写的枚举"两边都错在同一个地方是可能的。
   → **可操作化**:关键数值逻辑找**发表临界值 / 教科书算例**做锚,别只做内部对账。

4. **边界返回值要先问"它会被下游读成什么"。**
   E4:`0.0` 在数值上无害,在**语义**上等于"无效应",于是把退化洗成正常。
   → **可操作化**:区分「值 = 中性」与「值 = 无法计算」(用 `None`/`undefined`),
   尤其在下游会拿它做判定的地方。

5. **测试环境隔离要先想"配置从哪来",不只是"环境变量怎么设"。**
   E5:进程内环境变量不是唯一来源 —— `.env` 加载器会把它们**灌回来**。
   → **可操作化**:凡有 `.env`/配置加载器的项目,给测试一个**显式关闭开关**,并在测试里用它。
