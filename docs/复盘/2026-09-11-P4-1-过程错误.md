## 二、教训(下次可照做的规则)

1. **「跑通了」不是验证,「在测东西」才是。**
   E1 的产物有 N、有检出率、有 p 值,格式全对 —— 唯一的问题是那些数字没有意义。
   → **可操作化**:凡"重复 N 次"的实验,必须**断言重复之间确实不同**
   (取值多样性 / 种子不同 / 方差 > 0),否则 N 次的 N 是个装饰。

2. **测试必须走生产路径,尤其是"默认开着"的那部分。**
   E2 的根因:我按"最小调用"写测试,而生产默认会开观测。
   → **可操作化**:写测试前先问一句「生产默认配置是什么?我这个调用与它差在哪?」;
   差在关键开关上(观测/阈值/并发)时,测试按生产默认写。

3. **自洽的对账证明不了口径正确,要用外部锚点。**
   E3 里"实现 vs 自己写的枚举"两边都错在同一个地方是可能的。
   → **可操作化**:关键数值逻辑找**发表临界值 / 教科书算例**做锚,别只做内部对账。

4. **边界返回值要先问"它会被下游读成什么"。**
   E4:`0.0` 在数值上无害,在**语义**上等于"无效应",于是把退化洗成正常。
   → **可操作化**:区分「值 = 中性」与「值 = 无法计算」(用 `None`/`undefined`),
   尤其在下游会拿它做判定的地方。

5. **测试环境隔离要先想"配置从哪来",不只是"环境变量怎么设"。**
   E5:进程内环境变量不是唯一来源 —— `.env` 加载器会把它们**灌回来**。
   → **可操作化**:凡有 `.env`/配置加载器的项目,给测试一个**显式关闭开关**,并在测试里用它。

6. **"服务起得来" ≠ "被测答得了"。能力探针必须打真实请求。**
   E7 里 `/health` 返回 200(`database: ok, redis: ok`),看起来万事俱备 ——
   但一次真实问答立刻 500。若不先打这一枪,跑完的结果会被读成"被测质量崩了"。
   → **可操作化**:接真实被测的第一件事 = **发一条真实问答并检查答案非空**;
   失败则**先归因**(配置?镜像?第三方额度?),归因不清就不跑正式轮次。

7. **久置的容器镜像会撒谎。**
   E7:镜像/容器"存在且能启动"完全不代表它跑的是仓库当前的代码。
   → **可操作化**:用容器跑被测前,`md5sum` 对比镜像内文件与仓库文件 + 看 `docker inspect` 的构建时间;
   不一致就走**重建镜像**或**本机 venv** 两条已知路径之一,别直接用旧镜像。

8. **依赖缺口要"一次爆全",不要"崩一个补一个"。**
   E8:我按"起服务→崩→补一个件→再起"的循环走了 4 轮,每轮 ~4 分钟。
   → **可操作化**:恢复环境前先跑一次**全量导入探针**(把入口模块 import 一遍,收集全部 `ImportError`),
   再一次性补齐;或直接在**持久卷**里装依赖,避免每次重建容器都重装。

9. **零容忍门禁的"触发"必须逐条归因,不能直接上报。**
   E9:`redteam_zero` 响了,第一反应是"被测越权了";实际是被测换了个词拒答。
   → **可操作化**:凡 `redteam_zero` / 任何零容忍 blocker 触发,先做**三问**:
   ① 被测真的做了禁止的事吗?② 判据是用什么方式判的?③ 判据漏判的代价是什么?
   只有三问都指向"确实违规"才可上报为质量问题。

10. **判据的表达力有上限,而"零容忍"会把上限变成断崖。**
    E9 的深层:**契约不变量要求红队只走确定性引擎**(不能用 judge),于是"拒答判定"只能是规则 ——
    规则必然漏词。 ⇒ 越是"零容忍 + 必须确定性"的判据,越要把表达力做够(词表 → 模式),
    否则**判据的脆弱性会伪装成被测的违规**。

11. **报备的数字要用区间,并把实测值并列写回。**
    E10:单点估算 16,919 → 实际 23,654(+40%)。
    → **可操作化**:报备给**区间**(下界=上轮实测,上界=×1.5);跑完在摘要里**并列**报备值与实测值。
