# 复盘 · 2026-09-21 · DEC-022 实施中的两处过程错误

- 日期:2026-09-21 · 触发:**双自查**(本轮有失败/我方过程错误 ⇒ 当轮不算完成,直到落盘)
- 对象:DEC-022(`B5` 的**实施**,业务方 2026-09-21 授权开工)
- 两处**都发生在写代码/写数据的过程中**,且**都不是"忘了做",是"做了但做错"**。

## E1 · 写 JSON 时用了裸 ASCII 双引号 —— **这是第三次**

**事实**:往 `eval/fastapi_rag_golden.evals.json` 的 `_comment` 里写中文说明时,写了
`"任何百分比"`(**裸 ASCII `"`**)。该文件是 JSON ⇒ **整份文件解析失败**(line 5 col 793)。

**抓回方式**:`tests/test_schema.py::test_real_sut_golden_evalset_loads` **当场变红**
—— 不是我复查发现的,**是既有的结构抓住的**。修法:改用 `「任何百分比」`。

**⚠️ 为什么这条必须记**:**同一形状本仓已经记过两次** ——
① `tools/evidence_coverage_allowlist.json`;② 母体 KD-12 的构建脚本。
⇒ **这是第三次**。前两次的教训写进了复盘,但**没有变成"我下次不会再犯"** ——
因为教训是**文字**,而文字对"手滑"无效(本仓 `A1`/`A2` 的立库之基)。

**⇒ 结构在起作用**:第三次是**被测试抓住**的,不是被"我记得"抓住的。
这恰好印证本仓那一条:**纪律写在锚点里对"自己"有效,写在测试里对"所有人"有效。**

**判据(可照做)**:凡往 **JSON / YAML / 代码字符串**里写**中文说明**,
中文引号一律用 `「」`,⛔ **绝不用 `"` 或 `""`**。

## E2 · 突变验证按我自己的理解做,与 DEC 的措辞不符

**事实**:`DEC-022 §7.1④a` 写的是「去掉证据型判据的参与 ⇒ **② 必须红**」。
我第一次做突变时,按自己的理解"去掉证据检查"⇒ **红的是 ①,不是 ②**。

**根因**:证据型判据在实现里**有两个角色** —— ① 当"确定突破"的**证据**;② 当第三态的**触发器**。
我只拆了角色 ①,而 DEC 说的"去掉**参与**"是**两个角色都去掉**。

**修法**:重做突变(两个角色都去掉)⇒ ①② 同时红,**符合 DEC 措辞**。

**⚠️ 这条的价值**:如果我**没注意到**"红的是 ① 不是 ②"就直接写"突变验证通过",
那就变成 **`A5`(验证的假象)** —— 做了验证动作,但**验的不是 DEC 说的那件事**。
⇒ **判据**:突变验证跑完,要逐条对 **DEC 写的"必须红的是哪一条"**,
**对不上就是不符合**,不是"反正红了就算过"。

## E3(⚠️ **本轮最重的一条**)· 单元测试全绿,而「存疑**不阻断**」是**空头承诺**

**事实**:`DEC-022 §5.1` 承诺「存疑 ⇒ `flag`,退出码 **2**(**不阻断**)」。
单元测试**通过了**,但**端到端真跑**时:

```
存疑 1 条 · 红队突破 0        ← 语义对了
exit_code: 1                  ← ❌ 不是承诺的 2
blockers: ["l2_task_completion 未达标: 0.00 < 0.95"]
```

**根因**:`judged = passed + failed + flag` ⇒ **存疑计入 L2 分母** ⇒ 拉低 `completion`
⇒ `l2_task_completion` 阻断 ⇒ 退出码 1。**承诺的"不阻断"根本没发生。**

**⚠️ 为什么单元测试没抓住 —— 这才是要记的**:
那条测试用的阈值是 **`_NO_BLOCK_THRESHOLDS`(`l2 min = 0.0`)** ——
**它把 L2 关掉了**,于是 `exit_code == 2` 当然成立。
⇒ **它是"因为错误的理由"通过的**:测试写的是"存疑 ⇒ exit 2",
但它**从来没有在 L2 开着的情况下验过这件事**。

**这与本仓什么同族**:`A5`(**验证的假象**)—— "我做了验证动作" ≠ "这个验证真的能失败"。
⚠️ 而且它比 E1/E2 更隐蔽:**测试是绿的,并且绿得"看起来很有说服力"**
(它确实断言了 `verdict`、`flag`、`redteam_hits`、`judge_used`、`exit_code`)。

**抓到它的方式**:不看测试,去跑**一次真的** ——
端到端 CLI + **真实阈值** + 看**真实退出码**。
⚠️ 而且抓它的那次,我**差点又把退出码读错**:命令写成 `... | tail -4; echo $?`
—— `$?` 读的是 **`tail`** 的。⇒ 用**写文件 + 直接取 `$?`** 重测才拿到真值。
(同族:本仓已记过两次 `exit=$?` after a pipe。)

**落地判据(可照做)**:
> 凡断言「**退出码**」的测试,**必须使用生产阈值**(或显式写明本测试刻意关掉了哪一项,
> 以及**因此没验到什么**)。用宽松阈值验"严阈值下的行为",等于**没验**。

**修法与代价**:存疑**不进 L2 分母**(口径同 `skipped`:**不知道的事不算数**),
且「判到 0 条 ⇒ 不据 L2 阻断」(无测量证据而阻断 = 假警报;该拦的另有兜底)。
⚠️ **顺带修了一处会误导人的文案**:原先存疑的条被列在「**未通过** N 条」下、
归属写「硬层**拦下**」—— 而它**没有拦下任何东西**。
⇒ **让误报"有声" ≠ 让它"发错声"**:**错的信息比没有信息坏。**
