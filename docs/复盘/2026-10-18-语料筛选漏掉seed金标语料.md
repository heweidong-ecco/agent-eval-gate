## 二、教训(可复用的判断规则)

1. **隔离语料后,先用"期望事实反查"验收,再开跑。**
   做法:把评测集里每条 `answer_contains` / `answer_not_contains` 的关键事实拿去库里数一遍,例如:
   ```sql
   SELECT count(*) FROM documents WHERE content LIKE '%Starlette%';   -- id=4
   SELECT count(*) FROM documents WHERE content LIKE '%数千亿美元%';  -- id=10
   SELECT count(*) FROM documents WHERE content LIKE '%iPhone%';      -- id=47
   SELECT count(*) FROM documents WHERE content LIKE '%5800%';        -- id=43
   SELECT count(*) FROM documents WHERE content LIKE '%互补%';         -- id=20
   ```
   **任何一条为 0 ⇒ 语料不完整,不许开跑。**
   > 判据:过滤的正确性由"评测集需要的事实还在不在"定义,不由"source 名字看起来像不像测试数据"定义。

2. **任何会烧 token 的完整轮,开跑前做三项零成本预检:**
   - ① judge 连通性:1 次最小 `chat/completions`,必须是 **HTTP 200**;
   - ② 被测能力探针:能对真实问题作答(不是 `/health` 200);
   - ③ 会话预算余量:查 `token_usage_logs` 今日已用 + 预估本轮 ≈5 万,
     不足则显式设 `SESSION_TOKEN_LIMIT`。
   任一项不过 ⇒ **停在预检,不开全量**。

3. **失败归因先看"最直接的误伤判据",不要先怀疑判分器变严。**
   本轮有效判据是 `rule_hit_judge_fail`(字面命中却被判 fail)与失败答案本身;
   `rule_hit_judge_fail=0` + 失败答案确为拒答/未作答 ⇒ 先查语料/检索,而不是先改判分器。
