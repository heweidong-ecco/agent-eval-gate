## 二、教训(下次可照做的规则)

1. **门禁也需要门禁 —— 测门禁的测试必须有隔离边界。**
   F1 最反直觉:为了"防止门禁腐烂"而写的防腐测试,**自己成了新的腐烂源**。
   → **可操作化**:任何测试若会执行某个 hook/脚本,**必须先隔离其写入路径**(临时目录 + 环境变量),**并补一条断言"跑完本测试后,生产路径文件内容不变"**。

2. **门禁测试不得依赖工作区状态**(F2)。
   → **可操作化**:门禁类测试统一用 `git worktree` 在干净 HEAD 上跑,或显式构造临时仓库;禁止直接读当前工作区。

3. **关键结论必须在产出它的同一轮内落盘,不能"等会儿一起写"。**
   F3 的结论产生于 01:49,会话终止于 01:50 —— **窗口只有 1 分钟**。侥幸救回,但这是运气。
   → **可操作化**:长任务中,**每个"决定性证据 / 结论 / 缺陷发现"一旦产出,立即写进 `docs/复盘/` 或对应文档**,不等收尾。

4. **凡门禁上线,追问一句:"它依赖的证据,有没有可能被别的自动化流程写坏?"**
   F1 的证据链(`transcript → skill-trace.sh → latest.json → commit-msg`)有**四个环节**,而防腐测试写坏了第三个 —— 链条越长,越要有端到端断言。
