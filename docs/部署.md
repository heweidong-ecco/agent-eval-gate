# 部署与接入(安装 / 配置 / 接真实被测 / 环境坑)

> 对应 B 阶段3 产出物《部署配置》。受众:要把本评测门装起来、并接到自己 Agent 项目上的人。
> 本产品是 **CLI 工具**(纯 CLI 竖切,签核 D-3),**零运行时依赖**(纯标准库),无服务端、无数据库。

---

## 1. 前置

- Python **≥ 3.10**(CI 用 3.11;已验证 3.10 / 3.11)
- 若要跑**真实被测**:被测服务可达 + 其 API Key;若要跑**真实 judge**:一个 OpenAI 兼容端点的 Key

## 2. 安装

```bash
git clone <本仓> && cd agent-eval-gate
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'        # dev 含 pytest;运行时依赖为零
.venv/bin/python -m eval_gate run --evals eval/mini_rag_qa.evals.json --offline   # 自检
```

安装产物:控制台脚本 `eval-gate`(等价于 `python -m eval_gate`)。

## 3. 配置(`.env`,**不入库**)

复制 `.env.example` 为 `.env`。全部键位:

| 键 | 必填 | 说明 |
|---|---|---|
| `EVAL_JUDGE_BASE_URL` / `_API_KEY` / `_MODEL` | 真 judge 必填 | judge 走**任意 OpenAI 兼容端点**(DEC-002)。**三者缺一 → 自动回落离线 FakeJudge** |
| `EVAL_JUDGE_MAX_TOKENS` / `_CONCURRENCY` | | 默认 512 / 4 |
| `EVAL_SUT_FASTAPI_BASE_URL` / `_API_KEY` | 接真实被测必填 | 默认 `http://127.0.0.1:8000`;Key 走 **`X-API-Key`** 头(契约 `评测-sut-adapter.md:39`) |
| `EVAL_SUT_FASTAPI_SNAPSHOT` | | 指向快照文件则**改走快照回放**(总纲 D-5 的三种取法之一),用于被测不可用时 |
| `EVAL_LIVE` | | 置 `1` 才跑 `tests/test_live_smoke.py`(默认 skip) |
| `EVAL_TRACE` | | 置 `0` 关观测 |
| `EVAL_OTLP_ENDPOINT` | | 设了则把 span 外发 OTLP(Jaeger/Phoenix 可换) |
| `SSL_CERT_FILE` | 视环境 | **见 §6-1**,本机有 TLS 拦截时必设 |
| `EVAL_SUT_RETRIES` / `_BACKOFF_S` / `_429_BACKOFF_S` | | 重试次数(默认 2)/ 指数退避基数(1s)/ 429 限速退避(3s) |

**阈值**:运行值取 `eval/阈值.json`(人类可读说明见 `eval/阈值.md`)。文件缺失时**回落更严的兜底**(`min=0.9`)并告警 —— **绝不放宽门**。

## 4. 运行

```bash
# 单轮
.venv/bin/python -m eval_gate run --evals eval/fastapi_rag_golden.evals.json --report-dir eval/runs

# 看 Trace
.venv/bin/python -m eval_gate trace

# 采集结构化日志(stderr,JSON 一行一事)
.venv/bin/python -m eval_gate run ... 2>log.jsonl
```

**接入 CI**:见 `.github/workflows/eval-gate.yml` —— 要点是 **eval-gate 独立成 job**,不与代码门合并成一个绿灯;密钥走 CI secrets,不硬编码。

## 5. 接入一个真实被测(以 `01.FastAPI RAG Agent` 为例)

1. **起被测**:`cd <被测仓> && docker compose up -d`(确认 `curl http://127.0.0.1:8000/health` 通)
2. **拿被测 API Key**:被测的 `api_keys` 表里 `sk-` 开头的那把(管理端创建;网页登录口令**不是** API Key)
3. **seed 知识库(必做)**:契约 `评测-sut-adapter.md:42` —— 知识库不在 git,**首跑必须自带 golden 文档集 + seed 步骤**,否则检索结果不可复现,失败归因会失真(R2b 实测:未 seed 时失败全部指向知识库覆盖度,而非被测质量)
4. **本仓 `.env`** 填 `EVAL_SUT_FASTAPI_*` + `EVAL_JUDGE_*`
5. 跑:`python -m eval_gate run --evals eval/fastapi_rag_golden.evals.json`

## 6. ⚠️ 本机环境坑(全部真实踩过,照做即可避)

| # | 症状 | 根因 | 处置 |
|---|---|---|---|
| 1 | judge 全挂 `CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain` | 本机有 TLS 拦截,其 CA 只在**系统信任库**,不在 venv 默认 CA 集合 | 设 `SSL_CERT_FILE=/etc/ssl/cert.pem`(备选:certifi 的 `cacert.pem`) |
| 2 | 前几条成功,之后 `Connection reset by peer` | `localhost` 解析到 **IPv6**,而 `::1:8000` 被别的进程(Docker userland proxy)占着 | base_url 用 **`127.0.0.1`** 而非 `localhost` |
| 3 | `pip install` 卡在源码编译 `cryptography` | Intel Mac + 新版 cryptography 只发 **arm64 wheel** + 本机**无 Rust** | `pip install --prefer-binary ...`(回落到有 wheel 的版本) |
| 4 | 安装/构建极慢(单包 ~80 kB/s) | 国内镜像链路差(实测:阿里云 79 KB/s,官方 26,清华 0) | 择源;缓存已下载的 wheel 不会白费 |
| 5 | 本地服务反复被顶掉 | 同端口有**崩溃重启**的容器周期性抢占 | 先 `docker stop <该容器>` |
| 6 | judge 报模型不存在 / 行为变化 | 模型名被官方**停用**(如 2026-07-24 停用 `deepseek-chat`) | 换现行名(如 `deepseek-v4-flash`);**注意网关可能不校验模型名,返回 200 不代表名字有效** |

## 7. 故障排查速查

| 现象 | 先查 |
|---|---|
| exit 3 / `degraded` | 被测配额(`E_SUT_QUOTA`)→ 整批 aborted,属**熔断**而非"门坏了" |
| 大量 case 记 fail 且理由含"被测调用失败" | 看**真实异常类型** —— 可能是配置(未设 base_url/key)而非被测故障 |
| judge 全 flag | judge 端点/密钥/模型名;或模型返回非结构化 JSON |
| 阈值没生效 | 确认 `eval/阈值.json` 存在;**报告里 `applied_thresholds` 就是运行值** |

> 观测/审计:每次 run 的报告带 `run_id` / judge 模型 / `judge_usage`(成本);结构化日志与 Trace 可凭 `trace_id` 回溯整条链路。
