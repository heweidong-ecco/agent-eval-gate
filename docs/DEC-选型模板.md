# 选型 · 决策记录(DEC)模板

> 每个技术/产品选型开一份,进 `docs/decisions/DEC-<nnn>-<slug>.md`(编号递增)。留痕"为什么",供回溯/反悔。本模板 = 工程壳通用模板 + Agent Kit 补注。

## 补注(Agent Kit 特有用法)

- **选型对照源**:做技术选型时,先对照 B `知识库-Agent-System/07-外部参考与落地/07-参考-技术选型对比-v1.0.md`(框架/可观测/记忆/向量库/评估/沙箱选型对比,含适用场景·成本·锁仓风险·一句话结论)。
- **时效复核**:B `07-参考` 层为 2026-08-09 实时搜索,含价格与工具状态(如 Helicone 已并入 Mintlify、LangSmith Self-Hosted v0.13),**落地前复核时效与链接**,不以参考文件为最终断言。
- **反悔成本挂适配器层**:被构建系统的第三方依赖一律走"适配器抽象层 + 依赖监控"(引 B `03-横切设计原则/03-原则-信任进化与隔离-v1.0.md` §供应链),使 DEC 的"反悔成本"可量化到"换适配器实现"的代价。
- **通用 vs 领域**:基座(宿主/部署/DB…)选型与 **Agent 栈**(LangGraph/Claude Agent SDK/E2B/pgvector/OTel 等)是两层,分开记,避免误读为竞争(见 `01-B-全覆盖地图.md` / `02-增删映射表.md` §6-7)。

---

```markdown
# 决策记录:DEC-<nnn> · <决策事项>

- 日期:2026-09-09
- 状态:已采纳 / 待评审 / 已废止
- 关联:<阶段/模块/文件>(如:阶段2-步骤5 / 模块:记忆模块 / scaffold/agent/总纲.md)

## 决策事项
一句话:要解决什么问题、要选什么。

## 背景与约束
业务/技术上下文、时间与预算、团队(单人)限制、已有资产、B 参考结论。

## 备选方案(≥2)
| 方案 | 一句话思路 | 优点 | 缺点 |
|---|---|---|---|

## 评估标准
成本 / 开发速度 / 可维护 / 性能与规模 / 生态 / 单人可运维 / 安全合规 / 锁仓风险(按项目取权重)。
> Agent 系统额外权重:上下文/token 成本、可观测性(是否 OTel/OpenInference 防锁仓)、人在环中能力、回滚速度(秒级?)、评估集友好度。

## 方案对比(按标准打分或简述)
…

## 最终决策 + 理由
选哪个、为什么;放弃了什么、为何。
> 引用 B `07-参考-技术选型对比` 结论(如"评估工具是引擎,组织要自己定义质量模型")或你自设的依据。

## 影响与后续行动
改变了哪些 spec/契约/模板;要做的迁移或接线(如换向量库需全量重嵌入——引 B `05-模块-RAG检索增强`)。

## 反悔成本
若日后推翻,改什么、花多少(挂适配器抽象层 → 换实现 vs 换接口)。
```

> 参考栈之外的偏差一律先 DEC 后动。参考栈分两层:宿主/基座(部署/DB/监控宿主)与 Agent 栈(编排/可观测/记忆/向量库/沙箱/评估)——Agent 技术栈默认对照 B `07-参考-技术选型对比-v1.0.md` §六"一句话选型建议";宿主层与 Agent 栈的关系见 `02-增删映射表.md` §6-7(待核:是否新增 `01-blueprint-设计稿.md` 汇总两层默认,未定)。
