# RUNBOOK · Agent 系统开发主工作流(单人 · Claude 原生)

> **用途**:任何「新建 Agent 系统项目」的主 SOP。本文件**薄而指向 B**——六阶段的内容深度(入口/步骤/产出/门禁)全部在 B(`知识库-Agent-System/`)已写全,这里只给"下一步点哪个文件、过哪个门、留什么痕"。**不重抄 B,凡 B 已覆盖的细节一律给 `知识库-Agent-System/…` 路径回查**(防双份漂移)。
>
> 配套:角色分工见 `单人-角色映射.md`;选型一律 `DEC-选型模板.md`;记忆/事实纪律见 `memory-规约.md`;git/GitHub 留痕 × L1/L2/L3 挂钩见 `留痕×指标挂钩.md`;改 B 后同步见 `知识库同步映射.md`;CI/CD 骨架见 `github/ci-cd-骨架/`;Claude Code 配置见 `config/claude-settings.md`、`config/mcp-清单.md`。

## 路径约定
本文内凡写 `知识库-Agent-System/<某文件>` 均指**仓库根**下的 B 权威目录(本 Kit 迁入的领域知识库)。若你正从 `docs/` 出发,实际相对路径为 `../知识库-Agent-System/<某文件>`。

## 图例
- **入口**=何时可以开始本阶段(B 阶段卡「入口条件」);
- **产出**=必须留痕的物(B 阶段卡「产出物」;留痕=进 git/GitHub);
- **门**=可进下一阶段的唯一标准(B 阶段卡「本阶段门禁」清单);

## 一、指针导航映射(把 CLAUDE/ROADMAP 指进 B)

> 本 Kit 相对旧 Kit 的最大增量 = 「当前指针」能指到 B 的 **阶段×步骤×模块** 颗粒度(依据 02 增删映射表 §4-1)。任何 Agent 项目仓库的 `CLAUDE.md`「当前指针」字段按下列格式写,接续时读回该字段即可知道"现在在 B 的哪个位置"。

### 1.1 CLAUDE「当前指针」字段写法

```
分支 | 阶段X-步骤Y | 模块:<14 模块之一,可省> | L3基线:<…> | 北极星:<…>
```

例:`main | 阶段2-步骤4 | 模块:记忆模块 | L3基线:人工介入率 ≤30% | 北极星:自动解决率`

- `分支`:当前开发分支(main 或 `feat/<issue#>-<slug>`)。
- `阶段X-步骤Y`:引用 B 阶段编号与 12 步编号(见 §1.2 表)。
- `模块:…`:本节点正在精修的运行时模块(14 模块之一,可选——仅当该节点动到具体模块设计/实现时填)。
- `L3基线:…`:当前节点验收挂钩的业务指标基线(L3,可再带 L1/L2 关键阈值)。来源见 B `02-执行方法论/02-方法论-分层指标体系-v1.0.md`。
- `北极星:…`:统领性业务指标,见 B `agent-system-creator/SKILL.md`「步骤 12 北极星指标」。

## 二、六阶段执行卡(薄:入口 / 产出 / 门 / 分工)

> 每阶段完整「步骤动作 + 产出物 + 门禁 checklist + 应注入原则 + 相关文档」见 B 对应阶段卡。下表只留执行时高频要看的东西。

### 阶段一 · 需求与战略(B 步骤 1–2)——《痛点分析报告》起点
- **入口**:有明确候选业务场景,可获取现场观察/数据/访谈对象。
- **产出**:`04-阶段1` 列出的《痛点分析报告》《业务流程图(AS-IS)》《AI 可行性评估表》→ 步骤 2《技术方案设计书》《风险评估报告》《预算与时间估算》。
- **门**(完整 checklist 见 `04-阶段1` §四):痛点有数据/现场证据(非口头);ROI 为正;用例与成功标准明确;**仿真与 Walk-through 已走通**;数据分级/人机模式/合规初步识别。
- **分工**:你拍板"痛点真伪 / ROI / 是否立项";Claude 起草痛点分析/流程图/可行性评估初稿,你验收。

### 阶段二 · 架构设计(B 步骤 3–5)——《七层蓝图 + Agent 内核》
- **入口**:阶段一产出齐备;仿真门通过。
- **产出**:步骤 3《系统架构图(C4)》《组件职责说明》《数据流图》;步骤 4《Agent 内部状态设计》《记忆模块数据模型》《任务调度算法伪代码》;步骤 5 各模块详细设计文档。
- **门**(`04-阶段2` §五):蓝图覆盖七层;状态机/裁剪/记忆读写已定义;每模块有独立设计与接口;已注入安全/灾备/多租户/成本/可解释性;**评估数据集规划已启动**。
- **分工**:架构你定;契约/spec/模块设计由 Claude 起草 + 你 review。每选型开 DEC(引 `07-参考-技术选型对比-v1.0.md`)。

### 阶段三 · 工程实现(B 步骤 6–7)——《代码 + 存储/观测地基》
- **入口**:阶段二设计文档评审通过;接口契约已定义。
- **产出**:前端(极简统一入口)/后端(Router·Master·Sub-Agent·Sandbox·Self-Healing + 时序控制 + trace_id)/存储策略(结构化日志·OTel·向量库·缓存·备份)。
- **门**(`04-阶段3` §四):前端无业务逻辑;后端五组件已实现;时序控制生效;trace_id 贯穿;契约测试通过;Agent 推理链在沙箱+Mock 桩跑通;观测左移;存储落地。
- **分工**:节点引擎(spec→plan→TDD→实现→review)走 superpowers;你验收。**工程纪律四件事**(契约先行/TDD/观测左移/评估回归)见 `02-方法论-工程纪律与CI-CD-v1.0.md`。

### 阶段四 · 测试验证(B 步骤 8–9)——《上线前质量防线 + 评估集》
- **入口**:阶段三代码与存储落地;契约测试通过。
- **产出**:单元/集成/压测报告 + 红队安全测试报告(SKILL 增补)→ 系统端到端测试报告/性能基准数据 → **评估集纳入回归门禁**。
- **门**(`04-阶段4` §四):报告齐备且覆盖率达标;QPS/P99/错误率达基线;端到端跑通;性能基准沉淀;**本阶段产 L1/L2 基线**(供上线对比)。
- **分工**:测试/压测当"节点"写;红队/评估要领域判断,你抽查。评估纪律见 `05-模块-评估与测试`(先定阈值再看结果/版本化一切/污染控制/失败即补 case)。

### 阶段五 · 稳定性与鲁棒性(B 步骤 10)——《用对比数据证明可上线》
- **入口**:阶段四系统级测试通过,性能基线已沉淀。
- **产出**:容错/自愈实现并测试、混沌注入演练、《鲁棒性优化报告》《故障场景应对手册》(现象→影响面→应对→责任人)。
- **门**(`04-阶段5` §三):容错自愈已实现并测试;混沌演练通过;优化前后对比报告生成;灾备演练 MTTR 达标。
- **分工**:Claude 出降级链/自愈/混沌方案与报告初稿;你批准"风险接受度"(哪些故障场景可接受)。

### 阶段六 · 上线运营与持续改进(B 步骤 11–12)——《监控 + 灰度 + 数据飞轮》
- **入口**:阶段五鲁棒性报告与故障手册齐备。
- **产出**:监控面板配置/灰度发布报告/初期使用数据报告 + 运维日报/周度优化建议/版本迭代计划。
- **门**(`04-阶段6` §四,持续运营):L1/L2/L3 健康度仪表盘上线并联动预警;灰度可执行可回滚;告警与值班就位;日报/周报运转;反馈进数据飞轮。
- **北极星**:定统领业务指标把 L1/L2/L3 串起来(SKILL 步骤 12)。
- **分工**:投放节奏(影子→内测→灰度→全量)由你授权;Claude 准备监控/灰度脚本与对比报告;**发布授权 = 你**。

## 三、单人节奏

- **每天**:在 ROADMAP 推进 1 个节点到"可测"→ commit(conventional)。对照指针读 B 阶段卡/模块卡,先仿真/Walk-through 再写码(「纸面一小时,胜过返工一周」,引 `02-方法论-迭代交付与MVP-v1.0.md`)。
- **每 PR**:一条分支一个 PR;合并前至少一轮 review(superpowers 子代理代审);Critical/Important 清完才 merge。
- **每周**:复盘(阶段六步骤 12 精简版:本周哪些留痕挂了指标?评估集补了哪些 case?)+ 更新 ROADMAP 排期/风险/行动项 + 更新 CLAUDE「当前指针」。
- **MVP 先行**:不一次大瀑布;选一条端到端最小场景(覆盖核心价值/依赖最少/链路完整/可量化)先跑通 1–12 微循环,再横向扩展(引 `02-方法论-迭代交付与MVP`)。

## 四、留痕闭环(贯穿;详见 `留痕×指标挂钩.md`)

```
想法 → issue(#,label=模块+eval/prompt) → branch(feat/<issue#>-<slug>)
  → commit(conventional,引 issue) → PR(模板:必附 评估回归/是否改Prompt·工具·记忆/观测证据)
  → CI(代码门 lint/test/build + eval-gate 评估门,见 github/ci-cd-骨架/ci.yml)
  → review → merge → release(tag vX.Y.Z + 必附《L1/L2/L3 对比表》)
  → 监控事件 → 回写关联 issue(#) → 复盘(下一轮阶段一/06-优化)
```

> 每版本绑定评估报告与发布记录、模型/Prompt/评估集/代码同库管理可回滚(引 B `06-优化-版本迭代与发布策略-v1.0.md` §2.1)。
