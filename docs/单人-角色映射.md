# 单人-角色映射 · B 交付角色矩阵 折叠到「你 + Claude」

> **用途**:B 的交付物总览矩阵假设企业级多角色(BA/方案架构师/系统架构师/AI 架构师/模块负责人/前后端/平台/QA/测试负责人/SRE/运维/产品——见 `知识库-Agent-System/00-总览/00-全链路工作流-归档-v1.0.md` §六);本项目是**一人全栈 + Claude 原生**。本文件把 B 角色矩阵折叠到「你(拍板/验收)+ Claude(起草/执行)」两列,让每份产出物都有明确责任人。
>
> **防串义**:本文讲的是**开发期**的人机分工。B「多 Agent 协作与人机协同」原则(`03-横切设计原则/03-原则-多Agent协作与人机协同-v1.0.md`)讲的是**被构建系统运行期**的人机三模式(辅助/增强/自动化)——两者互补、不是一回事。

## 一、总原则

- **你 = 总工程师/产品/验收人/发布人**:真伪判断、ROI、预算、风险接受、对外承诺与上线授权——这些**拍板不外包**。
- **Claude = 虚拟团队**:各阶段产出物初稿/评估集/压测/CI 代码——起草 + 执行,**你验收后才算数**。
- 避免两个极端:全自动失控(Claude 说了算)/全手工没杠杆(什么都自己写)。

## 三、你拍板不外包的清单(红线)

1. **痛点真伪**:是否"解决一个不存在的问题"(B 步骤 1 最高优先级)。
2. **ROI / 预算**:ROI 是否为正;成本分层与预算上限(引 B `03-原则-成本与ROI-v1.0.md`、`06-优化-成本优化-v1.0.md`)。
3. **对外发布/上线授权**:影子/灰度/全量放量、Release 发布(引 B `06-优化-版本迭代与发布策略-v1.0.md`;真人授权上线见 `github/ci-cd-骨架/deploy.yml` 注释)。
4. **风险接受**:合规/安全/法律/数据分级判断(引 B `03-原则-安全合规与伦理-v1.0.md`)。
5. **范围与优先级**:MVP 竖切、边界、非目标。

## 四、Claude 起草、你验收的清单

- 各阶段产出物初稿(痛点/方案/蓝图/内核/模块/测试/报告)。
- 评估数据集骨架 + 阈值文件(你先定阈值再看结果——引 B `05-模块-评估与测试` §10.3"先定阈值再看结果")。
- 压测/混沌脚本、CI/CD 代码、监控面板配置。
- spec/plan/契约/代码(superpowers 引擎执行)。

## 五、交接与留痕(避免"AI 做了你不知道")

- 每次 Claude 交付,必须带:做了什么 / 测试证据 / 提交 hash / 未决 concern → 你 review 后合并。
- 一切决策进 DEC(`DEC-选型模板.md`)、一切变更进 git/GitHub;AI 输出与人类决定都有出处可回溯(见 `留痕×指标挂钩.md`)。
- 高风险放行(审校/上线/对外承诺)默认由你按确认,不静默全自动。

## 六、何时不信 Claude(带来源原则)

1. **需要外部事实/真实数据**(业务口径、法规、客户、市场)→ 你供事实源;若 Claude 去查,必须**带来源 + 置信度 + 标注"外部参考,非本公司事实"**,绝不冒充(引 B `07-外部参考与落地/07-参考-来源索引与链接-v1.0.md`;参考时效:2026-08-09 搜索,价格/工具状态可能已变,落地前复核——如 Helicone 并入 Mintlify、LangSmith Self-Hosted v0.13)。
2. **涉及钱/合规/对外承诺/发布** → 人确认(与总纲红线一致)。
3. **它说"完成了"但你没验证** → 回 `verification-before-completion` 技能,跑证据(命令输出/测试数/CI 链接),不凭口头断言。
4. **技术/合规表述** → 只准引用仓库事实源或 B 权威文件;AI 不凭空写储能/法规等专业内容。
