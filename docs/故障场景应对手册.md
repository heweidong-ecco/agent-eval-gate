- 责任人字段沿用 `docs/单人-角色映射.md:28` 的折叠:**业务方(拍板)/ Claude(起草)** —— 不虚构人名

## 0. 30 秒定位

```
先看 exit code → 再看 stderr 的结构化日志(module/action/status)→ 最后 eval-gate trace --run <id>
```

| exit | 含义 | 先做什么 |
|---|---|---|
| **0** | 全绿 | — |
| **1** | **被拦**(有 blocker) | 读 stderr 的 `blockers`:红队突破?L2 未达阈?L1 系统错误率?门自身开销? |
| **2** | **存疑需人工**(有 flag,如 judge 解析失败) | 读报告里的 `flag` 原因;判分器 `finish_reasons`/`attempts` 已在 trace 里 |
| **3** | **配置 / 运行错误** | 多为环境或配置:被测没起、密钥错、评测集坏、产物目录不可写、**整批 aborted** |

## 1. 被测侧故障(6 个错误码,`adapters.py:37-45`)

| 现象 | 影响面 | 应对动作(**已实现,非承诺**) | 责任人 |
|---|---|---|---|
| 被测**超时** `E_SUT_TIMEOUT` | 单条 | **指数退避重试 ≤2**(`EVAL_SUT_RETRIES`,基数 `EVAL_SUT_BACKOFF_S=1.0s`);耗尽后抛原错,该条记 fail | Claude(起草)/ 业务方(是否调 N) |
| 被测 **5xx / 过载** `E_SUT_5XX` | 单条 | 同上(指数退避) | 同上 |
| 被测 **429 限流** `E_SUT_4XX` + status 429 | 单条 | **限速退避**(基数 `EVAL_SUT_429_BACKOFF_S=3.0s`,更长) | 同上 |
| 被测 **4xx(非 429)** | 单条 | **fail-fast,不重试**(重试不会变好,只会拖长) | — |
| 被测**鉴权失败** `E_SUT_AUTH` | 整条链路 | **fail-fast**。检查 `.env` 的 `EVAL_SUT_FASTAPI_API_KEY` 与 `X-API-Key` 头 | 业务方(取 key) |
| 被测**配额耗尽** `E_SUT_QUOTA` | **整批** | **熔断**:整批 `aborted` → 阈值判定**作废** → **exit 3**(不据此报 L2 未达标,避免误判) | 业务方(恢复配额) |
| 响应**不可解析** `E_SUT_BAD_RESPONSE` | 单条 | fail-fast | Claude(起草) |

## 2. 判分器(judge)侧故障

| 现象 | 影响面 | 应对动作 | 责任人 |
|---|---|---|---|
| judge **不可达 / 抛异常** | 单条 | **该 case 记 fail + 错误码**,**不崩进程**;其余 case 继续跑 | Claude |
| judge **超时** `E_JUDGE_TIMEOUT` | 单条 | **重试 1 次** | Claude |
| judge **输出被截断**(`finish_reason=length`) | 单条 → flag | **放大预算 ×2(封顶 8192)+ 换提示语重试**(DEC-006)。根因:推理型模型的 `reasoning_tokens` 与 `content` **共用** `max_tokens` | Claude |
| judge **返回非 JSON** | 单条 → **flag(exit 2)** | 交人工;`attempts` / `finish_reasons` 已落 trace,可直接看"试了几次、每次为什么结束" | 业务方(判定是否算问题) |
| judge 整体不可用 | 整轮 | 拒绝把结果当真;**不得**静默回落到合成抖动(`ab_regression.py` 对 `--live` 有此守卫) | 业务方 |

## 3. 门自身 / 配置侧故障

| 现象 | 影响面 | 应对动作 | 责任人 |
|---|---|---|---|
| **默认阈值文件**(`eval/阈值.json`)缺失 / 损坏 / 形状不合法 | 判定口径 | **回落更严兜底 + 告警,继续跑**(`runner.py:117-124`);绝不放宽门。<br>⚠️ **兜底必须不松于生效值** —— 已加结构性守卫(`test_fallback_is_never_looser_than_the_threshold_file`) | Claude |
| ⚠️ **`--threshold <路径>` 显式指定的文件**读不到 / 结构不对 | 判定口径 | **`exit 3` 硬失败**,**不**回落兜底(`cli.py:91-99`)。<br>**为什么两条路径不同**:默认文件是"没配就用兜底";**显式指定**是操作者的明确指令 ⇒ 读不到就**停**,不静默换一套口径替他做决定。<br>📌 由 2026-09-13 故障演练发现(我最初把手册这条写错了 —— 演练的价值就在这) | Claude |
| **报告落盘失败**(`--report-dir` 指向已存在的文件 / 不可写) | 整轮 | **`exit 3`(配置/运行错误)**,并明确打印"**不是**质量不合格"。<br>⚠️ **曾是 exit 1 的真缺陷**(2026-09-13 故障演练发现):`mkdir(exist_ok=True)` 对**文件**仍抛 `FileExistsError` 且未被捕获 ⇒ 进程 exit 1 ⇒ **一个 IO 问题被读成"质量不合格"**。已修 + 加回归测试 | Claude |
| **`EVAL_TRACE=0`**(关观测) | **L1 不可测** | 记 **L1 阻断项**(exit 1):"**这是绕过口,不是通过**(不带 tracer = 绕开生产路径)" | Claude |
| **门自身编排开销超阈** | 整体 | blocker,文案**明确归因给门自己**(不是被测);⚠️ 带 **100ms 测量地板**(低于地板只报不判,因极短轮次由噪声支配) | Claude |
| **评测集不可解析 / 不存在** | 整轮 | **exit 3** | Claude |
| **产物目录不可写** | 整轮 | **早失败 exit 3**(不静默丢产物) | Claude |
| 被测输出含**孤立代理对** | 整轮崩(历史故障) | 已在 `SutOutput.__post_init__` **归一化**;红队曾打穿过,已修 | Claude |

## 4. 环境侧故障(本机真实踩过,详见 `docs/部署.md §6`)

| 现象 | 应对 |
|---|---|
| TLS 拦截,venv 默认 CA 不含 | 设 `SSL_CERT_FILE=/etc/ssl/cert.pem` |
| 被测 `localhost` 解析到 IPv6 → 打到错的容器 | 用 **`127.0.0.1`**(`.env` 里已是) |
| `/health` 返回 200 但答不了 | ⚠️ **必须跑能力探针**:`tools/sut-harness/run_sut.sh` 退出码 **2 = 起来了但答不了** |
| 模型名被停用 | DeepSeek 2026-07-24 起 `deepseek-chat`/`deepseek-reasoner` → **`deepseek-v4-flash` / `deepseek-v4-pro`**;⚠️ 该**网关不校验模型名**,能调通 ≠ 名字有效 |
| `git push` 偶发失败 | **传输抖动,重试 2–3 次即可**(与 CA 无关 —— 见 `docs/复盘/2026-09-12-推送失败归因未验证.md`)。<br>⚠️ **重试的判据要取命令自己的退出码**(`pipefail` 或独立核验 `git ls-remote`),别取管道尾部的 |

## 6. ⚠️ 本手册**未覆盖**什么(诚实列出)

1. **网络分区 / 服务宕机的"真混沌"** —— 本形态的等价物是"被测/judge 不可达"(§1/§2 已覆盖);
   真引入混沌框架**判不适用**(`DEC-014 §3 U2/U6` 同族理由:本地 CLI 无常驻依赖可分区)。
2. **断点续跑** —— **判不适用**(`DEC-014 §3 U6`);⚠️ 但**多轮实验**(如 A/B 的 20 轮/1 小时)**确实会因中断全丢**,
   该问题已登记为 **`KD-11`「长任务无断点保护」**,业务方指示「暂不处理」。
3. **灾备 / 恢复** —— 单列在 `docs/reports/P5-1/灾备演练记录.md`(「门的灾」= **证据链丢失**)。
4. **被测侧自身的故障**(它内部怎么降级)—— **不在门的职责内**;门只判它的输入→输出。
