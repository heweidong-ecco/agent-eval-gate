# DEC-003 · 测试与压测工具选型

- 日期:2026-09-11 · 状态:**已定**(本仓自决,理由见下;四项均**不改运行时依赖**)
- 上游:spec `docs/specs/P4-1-测试与压测.md` §2/§3(默认假设 1/2,业务方 2026-09-11 采纳)· 对应节点 ROADMAP `P4-1`
- 约束来源:`app/eval_gate/judge.py`「纯标准库 urllib,零依赖、防锁仓」是本仓既有红线

| # | 选型 | 决定 | 理由 | 被否方案与代价 |
|---|---|---|---|---|
| 1 | **覆盖率工具** | `pytest-cov`(**仅进 `[project.optional-dependencies] dev`**) | CI 一行接入(`--cov-fail-under=85`);`import eval_gate` 后仍**零第三方依赖** | 否:`trace` 模块自写统计 —— 精度差、要自己维护、还得自己实现下限判定 |
| 2 | **压测工具** | 标准库多线程 + **延迟桩适配器**,**不用 Locust** | 门是**串行 CLI 批处理**,不是长驻 HTTP 服务;B 卡的 Locust 面向"模拟并发用户打服务"的场景,**形态不符** | 否:Locust —— 需先给门**加 HTTP 服务形态**(超出阶段4 范围,且会引入 Web 依赖) |
| 3 | **统计工具** | **自实现** Mann-Whitney U + Cohen's d(精确枚举 / 正态近似双路,`app/eval_gate/stats.py`,~95 行) | ① 运行时零依赖是硬约束;② scipy 即便只进 dev 也 ~40MB 且拖慢 CI;③ 自实现可用**发表临界值**对账(已做:n=5/5、U=0 → `2/252`) | 否:scipy.stats —— 依赖重、把统计口径锁死在外部版本上(升级即可能改变判定)。**风险与对策**:自实现有算错的风险 → 用**外部锚点**(发表临界值)+ **独立枚举对账**双保险;实施中正是靠发表临界值抓到"精确 p 值多乘一倍"的缺陷 |
| 4 | **并发模型** | 多个**独立 `evaluate()` 线程**,**不改 `runner` 串行语义** | 串行语义是**已签核契约**(总纲 §1 不变量、契约 `评测-report.md`);并发只在**度量脚本**层面做,用于分离门开销 vs 外部开销 | 否:改 `runner` 内部并发 —— 会改变既有的确定性/日志顺序语义,**需单独 DEC**;本节点不做 |

## 影响面

- 运行时依赖:**零变化**(`import eval_gate` 仍只需标准库)。
- dev 依赖:`pytest-cov>=5` 一项(CI 与本地测试用)。
- 契约:**无漂移**(无需改任何 `contracts/`)。
- 产物:新增 `app/eval_gate/stats.py`、`app/eval_gate/bench.py`、`tools/ab_regression.py`、`tools/bench.py`,均纳入覆盖率门。
