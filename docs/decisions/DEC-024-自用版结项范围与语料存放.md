# DEC-024 · 自用版结项范围与语料存放

- 状态:**已实施**(2026-10-18)
- 类型:结项范围 + 数据存放决策
- 关联:`DEC-023`(live 回归环境)· `docs/结项报告-自用版-2026-10-18.md`

## 1. 背景

项目进入收尾。两个问题必须明确,否则"结项"会变成含糊的停更:

1. **评测语料放哪里?** 本仓是 **Public**,而被测知识库正文可能含业务内容;
2. **U2(接进真实被测的发版 CI)现在做不做?** 它必须改另一个仓
   (`fastapi-rag-agent` 是 Private),并配置 secrets、决定预算与触发。

## 2. 备选方案

### 2.1 语料存放

| 方案 | 做法 | 优点 | 代价 / 结论 |
|---|---|---|---|
| A. 正文进本仓 | 把 125 行语料 JSONL 提交到 `eval/corpus/` | 复现最简单 | **否决**:公开仓泄露正文;git 历史删不干净 |
| **B. 仓内清单 + 仓外正文(选定)** | 仓内只放 `manifest.json`(sha256/行数/来源计数);正文放 `~/Desktop/Product-external/eval-corpus/`(不在任何 git 仓) | 可校验、可复现、不泄露 | 换机器需先还原正文;seed 前必须过哈希 |
| C. 不固化语料 | 只记录"当时库里有 125 行" | 零成本 | **否决**:live 回归不可复现(本轮已因此浪费 43,303 token) |

### 2.2 U2 是否现在接

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A. 现在改另一个仓 | 在 `fastapi-rag-agent` 加 workflow + secrets + 语料供给 | 跨仓改动;每次 live ≈4 万 token;触发方式未定 | **业务方 2026-10-18 明确:暂不做** |
| **B. 本仓备模板、跨仓延后(选定)** | `integrations/fastapi-rag-agent/` 放 README + `eval-gate.yml.example`,标注**未接入** | U2 仍未闭环 | 选定;接入时的范围/顺序/验收已写清 |

### 2.3 版本号

- **`v0.4.0`(自用版,选定)** —— 只代表自用闭环,不代表可外化;
- `v1.0.0` **保留**,前置 = U2 接进真实发版 CI + 至少一个外部使用者验证。

## 3. 决策

1. 语料:**仓内清单 + 仓外正文**,`seed_eval_corpus.py` **强制校验 sha256**,不一致即拒绝;
2. U2:**本仓只备模板,不改另一个仓**;接入顺序与验收写在 `integrations/fastapi-rag-agent/README.md`;
3. 版本:**`v0.4.0` 自用版结项**;`v1.0.0` 不外推。

## 4. 认下的代价

- ⚠️ **U2 未闭环**:"劣化在真实发版 CI 被拦"目前仍只在手动流程成立;
- ⚠️ **换机器要还原语料**:正文不在任何 git 仓 ⇒ 只有本机 `Product-external` 有副本;
  (清单里的 sha256 让"缺/错语料"能被立刻发现,但它不能凭空恢复正文)
- ⚠️ **公开仓仍含评测问题与期望**(`eval/*.evals.json`),这是既有事实;
  本次只保证**不把知识库正文**再带进来。
