- **改动的已签核物**:`app/eval_gate/judge.py` 的 judge system prompt(**提示即代码**)⇒ 故须签核;
  按纪律**改了 Prompt 必跑 eval 回归**

## 1. 问题

M1 首测暴露的分歧**不是散乱噪声,是一个可命名的模式**:

| 条目 | 被测答 | 判分器 | 人(裁定口径) |
|---|---|---|---|
| `id=15` / `id=27` / `id=42旧` | 「无法回答…**但句中出现了候选词**」 | **flag**(存疑交人) | **pass** |

**根因**:judge 的 system prompt 只传达了「`answer_contains` 含其一即符」,
**没有说"在被测整句是拒答时,这个字面规则依然成立"** —— 模型于是按**常识**补位:
"它没真正回答问题 ⇒ 我拿不准 ⇒ flag"。

> ⇒ 这不是模型"笨",是**规则没写到反直觉的边界情形上**,执行者只能用常识填那个空。
> (同形教训见 `docs/复盘/2026-09-12-M1标注轮-判据口径未钉死.md` R1 —— 那一轮**人**犯的是同一个错。)

## 2. 决策:把边界写进 prompt

在 judge system prompt 里显式写明(与业务方裁定口径一致):

> ⚠️ **拒答语境的边界(必须照此判,不要用常识替代)**:被测整句是**拒答**(如「无法回答」「资料未提及」
> 「均不涉及 X」等)时,只要句中**出现了** `answer_contains` 里的任一候选词,**该期望即算满足 ⇒ 判 pass**;
> **不得**因为「它没有真正回答所问」「命中出现在否定性语境里」而改判 flag 或 fail。

并补一句消歧:判分看语义契合、容忍同义改写,**但「是否真正作答」不改变字面命中的结论**。

## 4. ⚠️ 本 DEC **刻意收窄**了一处,需业务方确认

业务方裁定的字面表述含**两种情形**:「即使整句是**拒答**/**答非所问**」。

本轮的 prompt **只写了「拒答」**。理由:

- **3 条分歧全是拒答语境** ⇒ 只写拒答就已达成 100% 验收,不需要更多;
- 把「答非所问」也写成放行条件,等于**让"关键词堆砌 + 答非所问"过关** ——
  那正是 **DEC-004 刻意保留的防堆砌闸**(「软层命中仍须 judge pass」),而业务方在 **`id=42` 处置时明确拒绝过**
  用规则引擎做等价的事(理由相同)。⇒ 同一取舍不应在 prompt 里**悄悄**发生第二次。

**⇒ 已定(业务方 2026-09-12 同意按 A)**:保持**只放开"拒答"语境**。理由(记下来,免得日后被当成疏漏再放开):

**放开"答非所问"会让一批现役用例直接失效** —— 软层是「含其一即符」,一旦规定"句中含候选词即满足",
**结论被答反的答案也会过关**:

| 用例 | 期望候选 | 一个**答反**的答案 | A(现状) | B(放开) |
|---|---|---|---|---|
| `id=45` 谁更擅长精确匹配关键词 | 关键词检索 / BM25 | 「**关键词检索**确实相关,但真正精确匹配的是向量检索」 | judge 可判 fail | **过关** |
| `id=14` FastAPI 和 LangChain 能一起用吗 | 提供 API / API 接口 | 「**不能**一起使用,虽然 FastAPI 提供 API 接口…」 | judge 可判 fail | **过关** |

`id=45` 属 **B3 方向性**维度(`DEC-005` 专为"**答反即不命中**"而加),放开 B 等于把它作废;
而"含候选词但结论相反"恰是**劣化最典型的样子**(被测开始胡说或检索串味时,它会复述材料里的词、却给出相反结论)。

**要防"答非所问",正确的位置是逐条硬层规则**(`answer_not_contains` 钉死已知错误结论),
**不是**全局放行 —— 与 DEC-004 的分层一致(硬层 = 确定性权威,软层留 judge 裁量)。

> 附注:裁定文本里的"答非所问"是**技术侧写选项时的措辞**,当时未料到它会作废方向性用例 —— 此处更正的是**描述**,不是业务方的判断。

**⚠️ 待测项(下一轮校准必须带上,用来证伪 A 的安全性)**:
加 2 条「堆砌/否定式」参照条目(句中堆了候选词、但整体答反,人判应 fail)。
- 若 judge 仍判 fail ⇒ **A 安全**,本 DEC 结案;
- 若 judge 也放过 ⇒ 说明**该收紧 prompt 措辞**(明确"结论相反不算命中"),而不是放宽 —— 那时另开 DEC。

已加测试 `test_prompt_does_not_license_passing_non_refusal_stuffing`:**若哪天把「答非所问」也写成放行条件,该测试会变红**
—— 那时必须先有 DEC,而不是顺手改。

## 5. 下一个校准轮的两点(本轮暴露的样本局限)

1. **1.00 说明这批样本"用尽"了** —— 15 条里已无不一致可学。下一轮**必须换新条目**(从新的真实 run 里取),
   否则再测只是复读同一个数。
2. **本参照集里没有"堆砌"条目** ⇒ §4 那个收窄的**风险未被测量**。
