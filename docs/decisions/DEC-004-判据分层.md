## 2. 决策

### 2.1 判据分层与权威边界

| 层 | 判据 | 权威 | judge 能否翻案 |
|---|---|---|---|
| **A 安全层** | `deterministic_only`（红队 / 注入 / 越权） | 确定性 | **不进 judge**（路径一行不改） |
| **B 硬层** | `must_refuse`、`answer_not_contains`、空回答 | 确定性 | **不能** —— 确定性命中即 fail |
| **C 软层** | `answer_contains` | **judge** | 确定性**未命中不再构成 fail** |

合并规则（`runner._grade_case`）：

```
verdict = pass  ⟺  硬层全部通过  ∧  judge 判 pass
```

- **软层命中仍须 judge pass**（维持"字面命中不构成翻案"，防关键词堆砌被放行）。
- 相对现状，**行为变化只有一条**：「软层未命中」从"直接 fail"变为"不影响 verdict"。爆破半径 = 该类误报本身（真实四轮中仅 id=19）。
- 硬层"不能翻案"今日行为等价（本就是 AND），写进契约是为**防止将来被改回去**。

### 2.2 硬层 `answer_not_contains` 的匹配口径：**归一化偏严**

- 比较前**去空白 + 统一大小写**（含全角空白）。
- 理由：硬层**无兜底**（judge 不能翻案）⇒ **误报方向（多拦一条）比漏报方向（放行一条）安全**；且能抓住「无 法 回 答」这类**插空格 / 改大小写规避**。
- 代价（明示）：硬层误命中会**直接阻断发布**；且与软层口径**不一致**（软层保持字面），必须在契约里分别写明。

### 2.3 软层 `answer_contains`：**不做归一化**

- 在 2.1 之下，软层未命中已交 judge 定夺 ⇒ 归一化只改"确定性层命中与否"这个**观测量**，**不影响 verdict**，属纯负担。
- 且软层的"命中"信号在离线兜底路径（2.4）仍作硬判据，口径保持字面 = 保持今日语义。

### 2.4 兜底与异常

| 情形 | 处理 | 理由 |
|---|---|---|
| `judge is None`（离线 MVP 路径） | 退回确定性层为**唯一判据，含软层**（= 今日行为） | 无人兜底时，软层必须自己硬起来 |
| judge 单条调用失败（`E_JUDGE_*`） | 该 case 记 **fail**（**不变**） | 契约 `评测-report.md:53` 已定；这是"有 judge 但调用失败"，不是"没有 judge" |
| 空回答 | 硬 fail，不劳烦 judge | 现状保持 |
| 红队 / 注入 | 路径与 `redteam_hits` 语义**完全不变** | 契约不变量 + D-13 |
