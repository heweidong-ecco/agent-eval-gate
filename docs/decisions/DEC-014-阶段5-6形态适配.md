## 1. 问题:阶段5/6 通篇假设"一个上线的服务"

B 阶段5/6 的门禁与产出物,默认对象是**有用户、有流量、有值班、有常驻服务**的系统
(监控面板 Grafana · 按流量百分比的金丝雀 · 钉钉/邮件告警 · 值班体系 · 运维日报)。

而本仓是**一个 CLI 工具**,且 `需求基线.md:157` 写明「**第一版使用者 = 你自己**……对外访谈尚未做」。
⇒ 照抄 B 会填满清单但产出**假门**(给没有用户的 CLI 建值班体系),正是本项目一贯治理的病症(避坑库 `A5`/`A4`)。

**定调结论(业务方 2026-09-13 拍板)**:逐条判「**落地 / 不适用 + 触发条件**」;
其中**不适用必须写明原因、并留下他人可读的记录**;受众按「唯一使用者 = 业务方本人」。

## 3. 不适用清单(逐条:**原因** + **触发条件**)

| # | 不适用的项 | **原因** | **何时该重开(触发条件)** |
|---|---|---|---|
| U1 | 【阶段6-1】常驻仪表盘(Grafana 类) | 门**不是常驻服务**,无常驻进程可挂面板;唯一使用者直接读 CI 结果与落盘产物,指标本身**已机读**(`eval/l1_baseline.json` / `run.*.local.json`) | 出现**第二个使用者**,或需要**跨项目汇总**多个被测的健康度时 |
| U2 | 【阶段6-2】按流量百分比的金丝雀发布 | 门**没有"流量/用户"对象**可切 10%/50%/100% | 门被**暴露为服务**(例:v1.1 的 Web 看板)时 |
| U3 | 【阶段6-3】外部告警通道(钉钉/邮件/IM)+ 值班体系 | **无外部受众**(唯一使用者即执行者)、**无值班主体**(单人);且从"出错"到"有人知道"的路径已由 **exit code + CI 红**闭合 | 出现**第一个外部使用者**,或门被接入**他人的 CI** 且需要响应时限(此时才需定义 P0–P2 的响应时限与通道) |

## 4. 本次新增/明确的约束(签核后生效)

1. **证据链归档纪律**(R3-1):**凡报告/复盘引用到的 trace,必须把"关键 span 摘录(脱敏)"随该节点归档进

   ⚠️ **不得**把 `eval/runs/*.local.json` 或整份 trace 直接入库 —— 它们**含被测答案原文**,
   与既有脱敏纪律(`runner.py` 结构性脱敏:`{len, sha8}`)冲突。
2. **面板占位处置**(R3-3):`observability/监控面板-清单.md` 的 9 处 `<…>` **逐条判** ——
   有对应物的填真实值(**一律取自 `eval/阈值.json`**);无对应物的**删占位 + 写明"本形态无此项 + 原因"**。
3. **告警定义**(B2):正式采用 **exit code + CI 红 + stderr 结构化日志** 为"告警",
   并写明"何种情况该有人看";外部通道按 U3 判不适用。
4. **手册责任人**(R3-4):《故障场景应对手册》的责任人字段沿用 `docs/单人-角色映射.md:28` 的折叠 ——
