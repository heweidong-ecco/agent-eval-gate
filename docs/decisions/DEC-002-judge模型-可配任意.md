# 决策记录:DEC-002 · LLM-as-Judge 模型可配任意 + 成本控制

- 日期:2026-09-09
- 状态:已采纳
- 关联:阶段1-步骤2 · 产出:`需求基线.md` §4/§7;阶段2 细化评测接口时落地适配器。

## 决策事项
一句话:评测门里的 LLM-as-Judge 用哪种模型策略——固定一家 vs 可配任意;以及如何控 judge token 成本。

## 背景与约束
- 已拍板(业务方 2026-09-09):judge 模型可配、自带 API key。
- 约束:防模型锁仓;成本可控(judge token 是持续运营成本,见 `需求基线.md` §5/§12);合规上企业或可切内网模型;B `03-横切设计原则/03-原则-信任进化与隔离` 强调供应链与可替换性,第三方依赖走适配器抽象层。
- B `07-参考-技术选型对比` 结论方向:"评估工具是引擎,组织自己定义质量模型" → 引擎不该绑死一家 judge。

## 备选方案(≥2)
| 方案 | 一句话思路 | 优点 | 缺点 |
|---|---|---|---|
| A · 固定单一模型 | judge 硬编码一家闭源模型 | 实现最简;输出口径稳定 | 锁仓;无法切内网/低成本模型;断供即瘫 |
| B · 可配任意(OpenAI 兼容适配器) | judge 通过统一适配器可配任意 OpenAI 兼容/Anthropic 端点 | 防锁仓;可切企业内模型/低成本模型;符合合规 | 需一层适配器 + 基准对齐(不同模型分数不可直接比) |
| C · 可配 + 内置参考基线 | B 之上,同一评测集同时跑 2 条"人工标注基线"校准 judge 漂移 | 最稳 | 略增阶段2 工作量 |

## 评估标准
锁仓风险 / 合规适配 / 成本可调 / 实现成本 / 输出口径一致性 / 单人可运维。

## 方案对比
- **A** 已被已拍板排除(锁仓不可接受)。
- **B** 满足"自带 key + 可配";风险是跨模型分数漂移 → 用**确定性规则不动 LLM** + judge 输出规范化(结构化分数/理由字段),并提示用户换模型需重标定阈值。
- **C** 是 B 的加固(人工基线校准 judge 漂移),与 `需求基线.md` §6 成功标准"judge-人工一致率 ≥ 阈值"同源,阶段2 顺手纳入,不另立决策。

## 最终决策 + 理由
**选 B(可配任意,统一适配器),阶段2 结合 C 的人工基线作校准。** 理由:自用先行决定了我们要把评测门挂进多个项目、可能切内网/低成本模型;固定一家会让"评测口径"依赖单一供应商(违背信任进化/供应链原则)。成本控制 = 自带 key + **限并发 + 抽样 + max_tokens 截断**(阶段2 设上限并在 `需求基线.md` §2 L1 成本栏沉淀)。
> 引用 B `03-原则-信任进化与隔离` §供应链:第三方依赖一律走"适配器抽象层 + 依赖监控",反悔成本量化到"换适配器实现"。

## 影响与后续行动
- judge 调用必须封装为统一接口(contracts/),不允许业务代码直连 SDK;换模型不改业务逻辑。
- 不同 judge 模型产出的分数**不可直接跨模型比**,需重标定阈值 → 记录在评测报告中(judge 版本/模型字段)。
- 阶段2:评测接口设计时落适配器 + 并发/抽样上限;阶段4 用迷你 RAG-QA 标定一致率与成本基线。

## 反悔成本
若日后确需单一固定模型(极端一致性场景),反悔 = 移除适配器分支 + 固定配置,成本低(适配器边界清晰);反之若一开始选 A 想切可配,则需重构所有直连调用——故现即选 B。
