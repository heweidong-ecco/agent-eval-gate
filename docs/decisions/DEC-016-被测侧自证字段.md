# DEC-016 · run 产物补**被测侧自证字段**(judge 侧已自证,被测侧没有)

- 日期:2026-09-13 · 状态:**已签核**(业务方 2026-09-13 指示「先把这条立成 DEC-016 并实现」)· **已实施(§5)**
- 上游:清欠账时查「**轮间 2× 延迟不稳**」—— **查不出根因**,而查不出的原因是**产物里没有被测侧字段**
- 改动范围:`app/eval_gate/runner.py` · `report.py` · `contracts/评测-report.md` · `tools/sut-harness/run_sut.sh` · `tests/`
- 预算:**零 token**

## 1. 起因:一条查不动的悬案,查出了**记录缺口**

P4-2 发现:同被测 `f2dad78`、同 48 条集,`sut.call` 合计 **187.0s vs 96.7s**(~2×)。

本轮**又排除了两个候选**(零 token,用既有 trace 判):

| 候选 | 检验 | 结果 |
|---|---|---|
| 被测侧**缓存/索引预热** | 轮内趋势(前半 vs 后半) | ❌ 三轮**都有**预热(11–26%),**慢的那轮趋势反而最弱** |
| 被测侧**重试退避**(1s/2s)拉长 span | 逐 case 差额分布是否聚在退避倍数 | ❌ **连续分布**(0.3s→3.3s),**不聚峰** |
| 成比例变慢 | 差额 vs 原耗时相关 | ❌ r = **−0.31**(弱负)⇒ 非倍率 |

**留下的**:~1.9s/条的**加性**开销、**只在被测路径**(同期 judge p50 稳定)、整轮均匀。

### ⚠️ 但真正的产出是这个:**查不动,是因为没有可比对的字段**

现有 run 产物顶层键:

```
applied_thresholds · blockers · cases · degraded · degraded_reason · evals_file
· exit_code · judge · judge_config · judge_usage · run_id · summary
```

**judge 侧记全了**(model/config/usage —— 这是 `DEC-006 A4`「产物里要能回答这轮实际用的什么预算」的成果),
**被测侧一个字段都没有**:版本 / endpoint / 启动方式 / 是否过能力探针 / adapter mode,**全无**。

⇒ 今天唯一查到的差异(慢的那轮 summary **没有**「能力探针通过」那句),是**从散文里读出来的**,
而且**无法证实**。**这个不对称本身就是缺陷。**

> 🔎 顺带:若当时录了 `base_url`,**今天就能直接看出**那轮走的是 `localhost` 还是 `127.0.0.1` ——
> 而那正是 `CLAUDE.md` 记着的一个坑(「localhost 解析到 IPv6 → 打到 Docker 的崩溃容器」)。
> **一个字段就能把悬案变成一次查询。**

## 2. 决策

**把 `DEC-006 A4` 对 judge 做的那件事,做到被测侧**:run 产物新增 `sut` 块,**自证"这轮跑的是什么"**。

| 字段 | 来源 | 缺省 |
|---|---|---|
| `sut.endpoints.<sut>.adapter` | 适配器类名 | — |
| `sut.endpoints.<sut>.base_url` | 适配器 `base_url` | `null`(如离线桩) |
| `sut.endpoints.<sut>.mode` | 适配器 `mode` | `null` |
| `sut.endpoints.<sut>.top_k` | 适配器 `top_k` | `null` |
| **`sut.versions.<sut>`** | 环境变量 `EVAL_SUT_VERSION`(**由 `sut-harness` 导出**),按 sut 落成映射 | `null` |
| **`sut.probe`** | 环境变量 `EVAL_SUT_PROBE`(`ok`/`fail`) | `null` |

**为什么 version/probe 用环境变量而不是门去猜**:门**不可能**知道被测的 commit,也不该自己去问 ——
那是 `tools/sut-harness`(它是唯一知道被测仓与探针结果的一层)的职责。
⇒ **缺省记为 `null` 而不是省略**:`null` 本身是信息("这轮没自证"),与"字段不存在"不同。

## 3. 边界(明确不做)

- ❌ **不补历史**(171456 那轮的真相**仍不可知** —— 字段当时没记,补不回来);
- ❌ 门**不主动去查**被测版本(那会让门依赖被测的仓库形态);
- ❌ 不因此**改变任何判定**(纯记录字段,不进阈值、不影响 exit code)。

## 4. 契约变更

`contracts/评测-report.md` 的报告顶层字段表新增 `sut` 块 —— **与实现同批**(免得漂移,`DEC-010c` 同例)。

## 5. ⚠️ 实施时发现:这不是新问题,是一处**已登记却一直没修**的契约漂移

翻契约时发现 `contracts/评测-report.md:20-28` **早就声明**了 run 记录的 11 个字段。
实测产物只有 4 个:

| 契约声明 | 产物里有? |
|---|---|
| `run_id` / `judge` / `degraded` / `degraded_reason` | ✅ |
| **`eval_version`** · **`evals_file_sha`** · **`sut_versions`** · **`threshold_rev`** · **`git_commit`** · **`started_at`** | ❌ **全缺** |
| `exit` | ⚠️ 实现叫 `exit_code`(名字不同) |

⚠️ 而该缺口 **`docs/部署.md:96` 于 2026-09-11 就登记了**(独立评审发现),**却一直没修**;
同期 P4-1 的《集成测试报告》还写着「契约**零漂移**」—— 那条结论**只覆盖了被抽查的字段**。

⇒ **DEC-016 因此扩大范围**:不只加"被测侧自证",而是**一次性把这条漂移关掉** ——
两者本就是同一个病:**产物不自证**。并把它做成**可机检**的测试
(`test_run_record_carries_all_contract_declared_fields`),而不是靠人记得核对。

### 三处形状差异,**如实声明**(不是静默对齐)

| 旧声明 | 现形态 | 为什么 |
|---|---|---|
| 顶层 `sut_versions: {sut: 版本}` | **`sut.versions`**(收进 `sut` 块) | 该字段**从未实现** ⇒ 无兼容负担;而"被测是谁/在哪/什么模式/什么版本"是**同一个问题** |
| `judge: {model, version}` | `judge`(标签)+ **`judge_config`** | `judge_config` 是 `DEC-006 A4` 加的**更完整**自证(含**预算**);两者合起来覆盖原意图 |
| `exit: 0` | **`exit_code`** | 实现/报告/复盘/CI **一律用 `exit_code`** ⇒ **把契约对齐到既有事实**,而不是反向改代码 |
