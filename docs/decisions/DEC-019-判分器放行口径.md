# DEC-019 · 判分器把「非拒答的答非所问」也放行了 —— 提示词自相矛盾

- 日期:2026-09-15 · 状态:**待签核**(草案;终裁 = 业务方)
- 上游:`DEC-009 §4`(**刻意收窄**:『含其一即符』**只在拒答语境**成立,不放行"答非所问")
  · `DEC-004`(判据分层:保留**防关键词堆砌闸**)· 收尾批次 `D-24` 的 PR-5(A2)
- **发现的来源**:A2 的**金丝雀**(`tools/judge_canary.py`,计划书 §六 验收②)
  —— 它是为"证明 A2 没让判分器变松"而建的,**结果先抓到了另一个洞**
- 预算:本次**已花 11,708**(金丝雀 5,914 + 对照 5,794)· 修它**另需 ≈5 万**(见 §5)

## 1. 发现(实测,含对照)

8 条"**必须被拦**"的构造答案(全部取自真实评测集的提问与期望,答案是我们故意写坏的),
逐条送真实 `deepseek-v4-flash` 判分器:

| | 放过 | id |
|---|---|---|
| **改动前**(A-safe,判分器仍收到 `deterministic`) | **3/8** | `[3, 13, 19]` |
| **改动后**(A2,不再收到) | **3/8** | `[3, 13, 19]` |

⇒ **与 A2 无关**(两次放过集合**完全相同**)⇒ 这是**既有洞**,A2 只是把它照出来了。

**被放过的 3 条全是同一类**(`kind=stacked_non_answer`):

| id | 提问 | 构造答案 | 为什么必须被拦 |
|---|---|---|---|
| 3 | FastAPI 是什么? | 「Web 框架、Python 框架、API 框架 —— 这几个词今天在社区里被反复提起,讨论热度一直很高,值得持续关注。」 | **堆齐了全部三个候选词,却没有回答"是什么"** |
| 13 | PostgreSQL 和 Redis 有什么区别? | 「关系型和内存都是数据库领域里很常见的说法,数据库技术本身非常重要。」 | 候选词都在,**没说出任何一条"区别"** |
| 19 | 多用户数据隔离如何实现? | 「这个话题很大,这里就不展开讲了。用户 ID 只是其中很小的一个点……」 | 含候选词,**明确回避了"如何实现"**(推诿,**不是拒答**) |

## 2. 判分器给的理由 —— 它**逐字引用了 DEC-009**

> 「依据 2026-09-12 人工校准口径(DEC-009):**即使该句未真正回答问题、命中词出现在
> 非实质性/框架性语境中,只要字面命中即判 pass**,不得改判 flag 或 fail」

它**不是**无视规则,而是**按它读到的规则**判的。⇒ 问题在**规则文本本身**。

## 3. 根因:提示词**自相矛盾**,而守卫只查了一个字符串

`judge.py` 的 system prompt 里,同一段话的**开头有条件、结尾无条件**:

| 位置 | 原文 | 读法 |
|---|---|---|
| 段首(**有条件**) | 「⚠️ **拒答语境的边界**……**被测整句是拒答**(如「无法回答」「资料未提及」等)**时**,只要句中出现了 `answer_contains` 里的任一候选词,该期望即算满足」 | 只在**拒答**语境 |
| 段尾(**无条件**) | 「但**「是否真正作答」不改变字面命中的结论**(见上条边界)。」 | **读起来是普遍规则** |

⇒ 模型按**段尾那句**(更明确、更接近"可执行规则")判 ⇒ 把豁免**扩大到了非拒答**。

**而守卫没抓到它**:`tests/test_judge_budget_truncation.py:229` 的判断是

```python
assert "答非所问" not in sysp.replace("答非所问时", "")
```

—— **纯字符串检查**。提示词里确实没写"答非所问"四个字,但它**语义上放行了**这一类。
⇒ **守卫与它要守的性质之间隔着一层**(同族教训见 `docs/复盘/2026-09-13-判据依赖了不该依赖的东西.md`)。

## 4. 影响面(如实,不夸大也不缩小)

**成立的部分**:

- **`DEC-004` 刻意保留的"防关键词堆砌闸",在"非拒答的答非所问"这一类上失效** ——
  而这正是 `DEC-009 §4` 明确**不放行**的那一类;
- 判据分层里 `rule_hit_judge_fail`(**字面命中但 judge 不认**)这个观测计数,
  对**这一类**永远不会触发 ⇒ 该观测**对这一类没有分辨力**;
- `DEC-009 §4` 的收窄**在文本上写了、在行为上没有生效** ——
  即"**记了但没落到判分器上**"。

**不成立的部分(刻意写清,免得被读成"门漏了")**:

- **本次 48 条真实评测集上,这一条没有造成误判** ——
  16 轮 A/B + 1 轮回归,**零 flag、零失败**,逐 case 恒定;
  也就是说:**洞是真的,但在当前样本上没有触发**(真实被测不会去堆期望候选词 —— 它看不到期望)。
- ⇒ 严重性是「**判据的设计意图没落地**」+「**某类退化没有分辨力**」,
  **不是**「已知有错判正在发生」。

## 5. 方案

| 方案 | 内容 | 成本 | 评价 |
|---|---|---|---|
| **α. 把提示词写成显式带条件**(**推荐**) | 段尾那句改成「**仅在拒答语境下**,『是否真正作答』不改变字面命中的结论」,并**给一个非拒答的答非所问反例** | 改 prompt ⇒ 须跑回归(**≈3.5 万/轮** + calibrate **≈1.4 万**) | 直接消除歧义;风险是判分器行为**会变**(可能收紧) |
| **β. 只升级守卫** | 把字符串检查换成"喂一条堆砌样本,断言判 fail" | 金丝雀已是这条(≈1.2 万/次) | **不改行为 ⇒ 洞还在**;但让洞**有守卫看着** |
| **γ. 加"堆砌"类参照条目** | 这正是 **B4(`T1b` judge 校准)** 的前置条件之一(`DEC-008 §5②`) | 已列入批次 | **让 calibrate 能测到这一类** |
| **δ. 维持现状 + 记录** | 只记 `DEC-019`,不动 | 0 | 已知问题不修;`DEC-009 §4` 的收窄继续**停留在文本上** |

### 推荐:**α + γ 合并进 B4(PR-6)**

**理由:不要单独修。** `B4` 本来就要:① 出**堆砌类**参照条目(`DEC-008 §5②` 的前置);
② 跑 `calibrate`;**③ 而这些都要花真实 token**。
⇒ 把 α 并进去,**一次回归覆盖两件事**,比单独立项省一轮钱(≈3.5 万)。

> ⚠️ **但顺序要注意**:α 改的是**判分器提示词**,而 `B4` 的参照集**已按 D-25 冻结(β 口径)**。
> α 会让判分器**更严**,而参照集里**没有堆砌类条目** ⇒ 改完 `calibrate` 的
> `judge_human_agreement` **可能下降** —— 那**不是回归**,是**仪器变准了**(同 `DEC-017` 的代价登记)。
> **⇒ 先加 γ(堆砌条目)、再改 α**,这样两头都在参照集里有对照。

## 6. 待业务方裁定

1. 采纳 **α + γ 合并进 B4**(推荐),还是 **α 单独立项先修**;
2. 承认 §4 的边界 —— 特别是「**洞是真的、但当前样本上没触发**」这句,
   **不要**读成"门漏了",也**不要**读成"没事";
3. 是否接受 **α 之后一致率可能下降**(那是仪器变准,不是回归);
4. 是否要把 β(守卫升级)也做了 —— 它不改行为,但能让"洞"这一层**有守卫看着**。
