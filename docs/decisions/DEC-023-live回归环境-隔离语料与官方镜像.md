# DEC-023 · live 回归的环境选择:隔离语料库 + 官方镜像

- 状态:**已实施**(2026-10-18,`DEC-019` 完整 live 回归)
- 类型:工程方法决策(非业务口径,无需业务方签核)
- 关联:`DEC-019`(判分器放行口径)· `DEC-018`(证据覆盖)· `DEC-014`(归档按需)

## 1. 背景(实测,不是推断)

跑 `DEC-019` 的完整 live 回归时,环境已经和旧文档不一致:

| 事实 | 实测 |
|---|---|
| 生产库 `rag_db` 的 `documents` | **345 行**;评测语料只占约 **125 行**,其余是其它项目/测试灌入(`a.md` 91、`test` 48、`isolation-seed` 16、demo/probe 等) |
| 被测仓结构 | 已从 `api/` 改为 **`app/`**(HEAD `150a963`,2026-10-18) |
| 官方镜像 | **`fastapi-rag-agent:latest`**(2 天前构建);旧 `my-fixed-name-api` 停留在 2026-07-01 |
| 旧 harness | `tools/sut-harness/run_sut.sh` 仍要求 `api/` + 旧镜像 ⇒ **直接跑会 `die`** |
| judge key | `EVAL_JUDGE_API_KEY` 曾失效(HTTP 401),业务方已更新 |

## 2. 备选方案与评估

| 方案 | 做法 | 优点 | 代价 / 为什么没选 |
|---|---|---|---|
| **A. 直接跑生产库** | 不隔离,`top_k=3` 面对 345 行 | 零准备成本;最接近"生产真实" | **失败无法归因**:无关语料挤占召回,分不清是被测退化、判分器变严还是语料污染 |
| **B. 清理生产库** | 删掉非评测语料 | 库变干净 | **破坏性**:生产库是共享数据,别的项目正在用;**否决** |
| **C. 隔离副本(选定)** | `CREATE DATABASE rag_eval_20261018 TEMPLATE rag_db` → 过滤 + 去重 → 125 行 | **原库一行不动**;失败可归因;可重复 | 需要准确识别评测语料;结果**不能直接代表生产库** |
| **D. 修旧 harness 后照旧跑** | 把 `run_sut.sh` 改到 `app/` | 保留旧路径 | 官方镜像已可用(harness README 的**退出条件**已满足);临时改 harness 会把"环境修复"混进本次回归;**推到单独待办** |
| **E. 回退被测到 `f2dad78`** | worktree checkout 旧版本 | 与历史 48/48 可比 | 业务方明确告知数据已变;目标是**当前链路**里验证判分器,不是复现旧基线;**否决** |

## 3. 决策

1. **语料**:用副本库 `rag_eval_20261018`,生产 `rag_db` 不写、不删;
2. **被测运行方式**:走官方镜像 `fastapi-rag-agent:latest`(按 `tools/sut-harness/README.md` 的退出条件);
3. **会话预算**:本轮容器临时设 `SESSION_TOKEN_LIMIT=200000`(新版被测默认 5 万,单轮会触顶);
4. **judge key**:使用业务方更新后的 `EVAL_JUDGE_API_KEY`;
5. **旧 harness**:不在本次修改,登记为**唯一环境待办**。

## 4. 认下的代价与边界(不得省略)

- ⚠️ **结果不能与历史 48/48 直接比较**:被测版本(`f2dad78` → `150a963`)与语料(70 篇 → 125 行)都变了;
- ⚠️ **隔离语料的正确性依赖"评测事实反查"** —— 本次第一版过滤漏掉了
  `eval_dataset.json#10–#25` 的 16 篇 seed,导致一轮 **37/48 的无效结果**;
  补救与防错见 `docs/复盘/2026-10-18-语料筛选漏掉seed金标语料.md`;
- ⚠️ **隔离库 ≠ 生产库**:它回答"判分器在真实链路里是否误伤",不回答"生产库当前质量如何";
- ⚠️ **旧 harness 仍是坏的**:下轮若照旧命令跑会直接失败,必须先修或改用本 DEC 的官方镜像命令。
