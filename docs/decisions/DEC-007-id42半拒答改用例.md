## 1. 现象与证据

标定轮里 `id=42` 的 flag **不是解析失败**(那条已由 DEC-006 修掉),而是**语义歧义**。判分器自己写道:

> 「被测输出字面出现了『快速部署』与『环境隔离』,按纯字面/近义命中规则本应判 pass。
> **但语境为否定性表述**:输出先声明『无法回答』,并明确『均不涉及 PostgreSQL』,
> 未把它表述为『用 Docker 部署 PostgreSQL 的好处』,语义上并未真正回答问题。……
> 建议人工裁定:若以字面命中为准应判 pass,若要求语义上确认这些好处适用于 PostgreSQL 则应判 fail。」

**语料核查(决定性的那一步)**:全库 `documents` 里含 Docker/PostgreSQL 的共 9 篇,逐篇看过:

| 文档 | 内容 |
|---|---|
| 3 / 65 | 「Docker 是一个容器化平台,可以将应用及其依赖打包成镜像,实现快速部署和环境隔离。」 |
| 57 | 「Docker 可以实现快速部署和环境隔离。」 |
| 52 | Docker 是容器化平台;Redis 是内存数据存储 |
| 67 | **「Docker 与 Redis 的配合方式:…容器化部署…Docker Compose 同时编排应用与 Redis 容器…」** |
| 5 / 53 / 66 | PostgreSQL 是开源关系型数据库(支持 JSON / 全文搜索 / 扩展插件) |
| 71 | 本系统三种数据库及职责 |

⇒ **没有任何一篇说"用 Docker 部署 PostgreSQL 有什么好处"**。该问题要求把 Docker 的通用好处**推断**到
PostgreSQL 场景;被测回答「无法回答…仅说明 Docker 一般可实现快速部署和环境隔离…均不涉及 PostgreSQL」
是**如实作答、没有编造**,且**确实召回了** Docker 那几篇(不是检索漏召)。

⇒ **这不是被测缺陷,也不是判据 bug** —— 是**用例问法超出了语料依据**。

## 2. 为什么「逐条判 pass」无法直接实现(结构性约束)

业务方先选定「① 判 pass(软层字面命中即算)」。核查实现时发现**这条在用例层面没有合法落点**:

`app/eval_gate/schema.py:101-105`:

```
if checks.deterministic_only and not (expected.must_refuse or expected.answer_not_contains):
    raise EvalError("… case id={cid} 标记 deterministic_only,但 expected 缺机器规则 …")
```

即:**标 `deterministic_only`(该条只走确定性层)的用例,expected 必须有机器规则**。
而 `id=42` 的期望是 `answer_contains` —— 按 **DEC-004 分层**,`answer_contains` 属**软层 = judge 权威**,
**故意不算机器规则**(否则等于承认"关键词命中即真理")。

⇒ 想让它"只按字面判",只能改**全局口径**;而全局口径是有代价的(见 §4)。
**此处更正我自己的表述**:初次给业务方的选项里,把 ① 的代价说成"该条信息量下降",
**说小了** —— 若走全局口径,代价是**整个门的防关键词堆砌闸消失**。业务方据此重新选择 ⇒ 本 DEC 的结果。

## 3. 决策:改写 `id=42`

**改动**(`eval/fastapi_rag_golden.evals.json`):

| | 原(as-is) | 新(to-be) |
|---|---|---|
| 问题 | 用 Docker 部署 PostgreSQL 能带来哪些好处？ | **知识库里介绍 Docker 与 Redis 如何配合使用？** |
| 期望 | `answer_contains`: 环境隔离 / 快速部署 / 容器化 | `answer_contains`: **容器化部署 / Docker Compose / 编排** / 环境隔离 / 快速部署 |
| 依据语料 | 3/5/65(**无效**:语料无二者结合) | **67(主)** + 3/52/65(Docker 通用) |
| 维度 | B1 多跳/跨文档 | **B1 多跳/跨文档(不变)** |

**为什么这条新问法更好**(不是"把题改简单"):

- **语料真的有答案**(§1 全库核查),被测**直接作答**、不再触发半拒答;
- **判别力不降**:候选里 `Docker Compose` / `容器化部署` 是**退化系统会漏的具体信息**
  (旧的三个候选全是 Docker 的通用好处词,反而更容易被"泛泛而谈"命中);
- 仍是**跨文档**题(需要区分 67 / 52 / 5 三篇各说了什么)。

## 6. 附带发现(已在标定轮摘要记录,单列待办)

`deterministic.hits` 的**字段名与语义不符**:它是"问题清单"(硬层失败原因 + 软层未命中提示),
**软层命中时为空** ⇒ `passed=true, hits=[]` 是设计如此。但我们**把它原样喂给判分器且未加说明**,
判分器据此认为「字面命中与判定不一致」,并**把它算进了不确定性** ⇒ **可能是本条判 flag 的助推因素之一**。
性质:**可解释性缺陷**(非逻辑错误),归属:`DEC-004` 分层的副作用。**处置待定,须单独 DEC**(改的是判分器看得到的内容)。
