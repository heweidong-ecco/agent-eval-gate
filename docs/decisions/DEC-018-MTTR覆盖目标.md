## 1. 问题:B 要求「MTTR 达标」,而本仓**从未定过目标值**

`docs/RUNBOOK.md:117` 引 B 阶段5 门禁原文:「灾备演练记录 **MTTR 达标**」。
但 2026-09-13 的 grilling 复核(`notes/grilling/M5-形态适配-2026-09-13.md`)查明:
**`MTTR` 在本仓 7 处出现,全是规划占位,零实测** —— 自然也没有目标值。
⇒ **D-20 签核时把它明确挂账**(「MTTR 目标值未定」),而不是记成"达标"。

**要定的就是这个目标值。** 而本条 DEC 的结论是:**它不该是一个"值"。**

## 2. 为什么「时间目标」在本仓**没有落点**

P5-1 的实测(`灾备演练记录.md §5`)给出的形状是**二值的**:

| 证据状态 | 恢复表现 |
|---|---|
| **已归档**(git 里有 `<run_id>.spans.jsonl`) | **≈1 秒**(从 `git show` 取归档 + 重算,逐字一致) |
| **未归档** | **不可恢复(无界)** —— 不是"恢复得慢",是 `exit 3`,**根本恢复不了** |

⇒ 在这个形状下问「MTTR 是几秒」是**问错了量**:

- **没有连续量可优化**。已归档侧的 1 秒是**机器速度**(`git show` + 一次纯本地重算),
  拿它定目标等于给"读文件有多快"定 SLA —— 它不会因为我们的努力而改善;
- **真正的风险全在未归档侧**,而那里的值是**∞**,不是某个秒数;
- ⇒ 一个有意义的"时间目标"**要么不可优化(1s),要么恒为∞(未归档)**。**两者都不是可供管理的指标。**

⚠️ 本文**不主张`MTTR` 这个词在本仓无意义** —— 它主张的是:
**在"结论入库、原始证据不入库"这个刻意选择之下,可守的量是"缺口数",不是"秒数"。**

## 3. 覆盖目标(取代时间目标)

> ### **凡被结论性产物指名引用的 run,必须在 git 里有 `<run_id>.spans.jsonl` 归档。**

这条目标有四个它必须有的性质:

| 性质 | 为什么必须有 |
|---|---|
| **可二值判定** | 每个 run 要么有归档要么没有 ⇒ 没有"差不多达标"的模糊地带 |
| **可优化** | 补归档是一次 `tools/archive_evidence.py` 调用(≈0 成本),**努力能直接改善这个数** |
| **有唯一定义** | "被引用"由工具**机械抽取**,不靠人回忆 |
| **能变红** | 缺一个就 `exit 1` ⇒ 可接进 CI,**不依赖谁记得** |

### 3.1 「被引用」的边界(刻意写死)

| | 内容 |
|---|---|
| **扫** | `*.md`(文档/报告/复盘/决策/摘要)+ `tools/*.sh` |
| **不扫** | 代码文件(`*.py`)—— 早先的临时 grep 把**代码注释里的 run id** 也当引用,那会把"实现细节里提过一嘴"变成归档义务 |
| **跳过** | `.git` / `.venv` / `.claude`(后者含 worktree 副本,不跳会把同一份文档数两遍) |
| **不追溯扩大** | "没被引用的 run 不必归档"是 `DEC-014 §4.1` 的**刻意口径**,不是漏洞 |

## 4. 落地:三件东西 + 一个触发点

| 产物 | 作用 |
|---|---|
| `tools/check_evidence_coverage.py` | 抽引用 → 对归档 → 报覆盖率;有缺口 `exit 1` |
| `tools/evidence_coverage_allowlist.json` | 「已引用但**确认不可恢复**」的清单,**每条必须写理由** |
| `tests/test_evidence_coverage.py` | 9 条:含**本仓自身必须通过**那条 |
| **触发点** | 上面最后一条测试 ⇒ 守卫**随 `pytest` 进 CI** |

> **为什么必须有那个触发点**:本仓反复踩过同一个坑 ——
> **"装了 skills ≠ 会用 skills"**(避坑库 `A2`)、**"纪律不在每会话必读的文件里 = 等于没有"**。
> 一个只躺在 `tools/` 里的脚本,和一句只写在文档里的规矩**是同一种东西:没有触发点**。
> 没有那条测试,这个守卫**永远不会被执行**。

### 4.1 三条"不许静默"(工具设计)

1. **允许 ≠ 隐藏**:允许清单里的项**仍然打印**(否则清单变成"遗忘"的容器);
2. **裸条目不算**:没写理由的允许条目 ⇒ `exit 1`(同 `[no-test: <理由>]` 的既有约定);
3. **清单不得腐烂**:允许清单里"其实已归档"的项 ⇒ `exit 1`,逼着清理 ——
   否则它会慢慢变成"没人记得为什么"的垃圾场,**悄悄放宽守卫**。

## 5. 实施时的实测(2026-09-15)

**首次运行 = 35.7%**。工具第一次跑就抓出了**9 个此前完全无声的缺口**:

```
[证据覆盖] 引用面 107 个文件 · 被引用 run 14 个
           已归档 5/14 (35.7%)
   ❌ **缺口**:9 个被引用但**未归档**的 run
```

**处置**(逐条):

| | 数量 | 做法 |
|---|---|---|
| **当场补归档** | **8** | `tools/archive_evidence.py` ⇒ **逐条复算验证** |
| **确认不可恢复** | 1 | 写进允许清单,**带理由** |
| **处理后覆盖率** | | **13/14 = 92.9%**,`exit 0` |

**补归档的 8 条不是"补了就算"** —— 逐条做了**往返验证**(归档改名回 `.trace.jsonl` 后重算,
与原始 trace 的统计**逐字一致**)。实测:`n=40`、`p50`/`p95` 全等,8/8 通过。

> ⚠️ 这一步**必须做**。归档若重算不出同样的数,它就**只是安慰剂** ——
> 而"归档文件存在"这件事本身**不会告诉你它够不够用**。

**唯一不可恢复的那条**(`20260910-193433-492c6fe4`):

- 该轮 `19:34:33` **早于**本仓最早落盘的 trace(`20260910-195009`,`19:50:09`);
- ⇒ R1a 快照冒烟时 **tracer(E9/R3)尚未落地,该轮从未写过 trace** —— **不是丢了**;
- 结论(`.summary.md`)在 git 里,**原始证据不可恢复**。

## 6. 代价与边界(签核时认下)

1. ⚠️ **它管不了"没被引用的证据"**。`DEC-014 §4.1` 的口径是**按需归档** ⇒
   **没被引用的 run 丢了就是丢了**,覆盖率对此**永远是 100%**。
   这是刻意的(否则归档成本随每次运行无限增长),但**必须说出来** ——
   覆盖率 92.9% **不等于**"本仓证据 92.9% 可恢复"。
2. ⚠️ **它只保证"能重算",不保证"算出来是对的"**。归档的是**结构字段**,
   被测答案原文**刻意不入库**(脱敏是硬约束)⇒ 涉及**答案内容**的结论**不可从归档复现**。
3. ⚠️ **8 个归档是补的,不是事发当时归档的**。它们能重算,但**没有被"按需归档"流程在第一时间保护过** ——
   若那几天机器丢了,这 8 条同样会永久消失。**这次是运气**。
4. ⚠️ **接进 CI 意味着"引用面"变成了约束**:今后任何报告引用一个未归档的 run,CI 会红。
   补救路径有两条(补归档 / 加带理由的允许条目),但**这是一条新的 CI 义务**,须业务方认可。

## 7. 被否方案

| 方案 | 否因 |
|---|---|
| **定一个 MTTR 秒数**(如"≤5 分钟") | 无落点(§2):已归档侧是机器速度(不可优化),未归档侧是 ∞。**定了也不会有人因为这条数而做任何事。** |
| **要求"全部 trace 都归档"** | 成本随每次运行无限增长,收益为零;且与 `DEC-014 §4.1` 的按需口径直接冲突 |
| **只写文档、不写工具** | 本仓的既有教训:写成文字的规矩**没有触发点 = 早晚会漏** |
| **把守卫做成"只报告、退出码恒 0"** | 那就退化成"另一个没人看的仪表盘"(同 `DEC-014` U1 判不适用常驻仪表盘的理由) |

## 8. 待业务方裁定

1. **「覆盖目标」这条口径本身**是否采纳(§3);
2. **允许清单的"只增不减会被拦"**(§4.1 第 3 条)是否过严 —— 它会拦"补了归档却忘删条目";
3. **接进 CI**(§6 第 4 条)是否认可 —— 这是本条的**唯一新增义务**;
4. 承认 §6 的四条边界,**特别是第 3 条(这次是运气)**。
