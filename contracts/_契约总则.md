# contracts/ · 契约总则(跨模块一致性的单一来源 · Agent 版)

> 模块并行开发靠契约解耦。**契约先行定义,模块 spec import 它;改契约 = 先 DEC + 通知,不允许单模块静默漂移。**
> 依据:B 阶段3 工程纪律「接口契约先行」(`02-方法论-工程纪律与CI-CD`)+ `05-模块-工具注册与MCP`(工具即契约)。

## 契约对象(本项目四类)

```
contracts/
  api/            # 前端(极简入口)↔ 后端 · 运营后台 Console ↔ 后端  的 HTTP/WS 契约
  agent-message/  # Agent 间消息协议(编排/黑板/子任务结果;版本化)
  tools-mcp/      # 工具/MCP Schema 注册(工具即契约:名称/描述/入出参 Schema/权限/重试)
  data-model/     # 领域模型、记忆数据模型、向量集合、表结构与迁移方向
  standards/      # 日志/命名/trace 规范(引 observability/)
```

## 一份契约文件的结构
```markdown
# <域> 契约
- 版本 / 负责人 / 状态
## 术语
## 数据模型(字段/类型/必填/枚举/约束)
## 接口(方法/路径或消息类型/鉴权/请求/响应/错误码)
## 变更记录
```

## 关键约定

### 1. 工具 / MCP Schema 注册(挂 `05-模块-工具注册与MCP`)
- 每个工具登记:`名称(动作命名,如 create_issue)` + `描述` + `inputSchema/outputSchema` + `isError:true 结构化错误` + `权限要求(按 Agent 身份)` + `重试策略`。
- **规模控制:5–15 工具/服务器**(超出拆分;工具定义占上下文)。凭证放环境变量,不入库。
- **工具即契约**:改 Schema = 契约版本变更 + 契约测试;未接真实 API 前用 Mock 桩(工具桩先跑通推理链)。

### 2. Agent 间消息协议(挂 `05-模块-子Agent与多Agent编排` + B 03 原则 多Agent协作)
- 消息结构最小字段:`message_id / trace_id / from / to / type / payload / ts / version`;共享黑板(Blackboard)独立于消息流。
- 消息协议**版本化**,新增字段向后兼容;冲突仲裁(投票/置信度加权/上报 Master)结果写回审计。
- 子 Agent 只经协议通信,不直改他人状态(单一 typed state)。

### 3. Console / 前端边界(挂 agent-system-creator SKILL.md 步骤 6)
- **前端(用户入口)**:只调 `api/` 的对话接口,不含业务逻辑/路由/多 Agent 协作。
- **运营后台(Console)**:只调 `api/` 的管理接口(知识库 CRUD+版本/灰度、Prompt 配置、会话接管、看板);不得耦合 Agent 内部状态。
- 前后端任何一端出现与契约不符的逻辑 = 契约漂移 bug(评审/CI 体检可查)。

### 4. 版本纪律
1. 新模块先在这里立项接口与模型,再让前后端/多模块按此实现。
2. 改动契约 = 新版本 + 变更记录 + (跨模块/跨端时)通知相关方。
3. **版本化一切**(B 评估与测试 / 版本迭代):契约、Prompt、评估集、模型 revision、代码同库可回滚。
4. 单一事实源:冲突以本目录为准,回总纲对齐后改。
